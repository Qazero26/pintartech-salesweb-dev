FASA 1

1. Cloudflare DNS

Apa Benda Ini?

DNS (Domain Name System) ialah "buku telefon internet" yang menukar nama domain manusia mudah ingat kepada destinasi IP / Hostname server.

Konsep Asas Utama

  • • A Record: Peta Domain ➔ IPv4 Server
  • • CNAME: Alias Domain ➔ Hostname lain (Tunnel)
  • • Propagation: Masa untuk kemaskini DNS tersebar global
  • • Proxied (Awan Jingga): Trafik lalu Cloudflare (Lebih selamat)
  • • DNS-only (Awan Kelabu): Trafik terus ke server asal
Aliran Pemetaan DNS
app.domainbos.com
↓ (Meminta Resolusi DNS)
Cloudflare Global DNS Anycast Network
↓ (Hala Ke Tunnel Hostname)
<TUNNEL_ID>.cfargotunnel.com ➔ Server Anda
Modul 04 dari 40 Asas Identiti Domain
FASA 1 — CLOUDFLARE DNS

Kenapa DNS Penting Untuk Self-Hosting?

❌ Tanpa Custom Domain

https://a1b2c3d4-random-address.example.net

  • Sukar diingati oleh pengguna/rakan.
  • Alamat bertukar setiap kali tunnel diwujudkan semula.
  • Kelihatan tidak profesional dan sukar untuk SSL persendirian.
✅ Dengan Cloudflare DNS & Domain

https://app.domainbos.com

  • Mudah diingati dan konsisten selamanya.
  • Boleh dibuat pelbagai subdomain (api., admin., dev.).
  • Perlindungan DDoS dan caching automatik di Edge.
Pengguna ➔ app.domainbos.com ➔ Cloudflare DNS ➔ Local Server
Modul 05 dari 40 Pengurusan Nama & Identiti
FASA 1 — CLOUDFLARE DNS

Perbandingan Rekod DNS Utama

Jenis-jenis rekod yang biasa dikendalikan dalam dashboard Cloudflare DNS.

A RECORD IPv4 Direct

Menghala nama domain terus ke alamat IP public IPv4 (Contoh: 203.0.113.195).

CNAME RECORD Alias Hostname

Menghala domain ke domain/hostname lain. Digunakan secara meluas oleh Cloudflare Tunnel.

AAAA RECORD IPv6 Direct

Menghala nama domain terus ke alamat IPv6 128-bit.

TXT / MX RECORD Info / Mail

MX: Hala trafik email. TXT: Pengesahan kepemilikan domain & sekuriti SPF/DKIM.

Nota Self-Host: Fokus utama kita dalam Cloudflare Tunnel ialah CNAME Record kerana Tunnel menguruskan routing secara automatik tanpa pendedahan IP Public.

Modul 07 dari 40 Keselamatan Sambungan
FASA 2 — SSL/TLS

3 Teras Utama Perlindungan TLS

1

Encryption

Menyulitkan data yang dihantar supaya mana-mana pihak ketiga di tengah rangkaian (ISP, Public Wi-Fi) tidak dapat membaca isi kandungan.

2

Authentication

Mengesahkan bahawa pengguna benar-benar berhubung dengan pelayan sasaran yang sah menerusi Sijil Digital (Digital Certificate).

3

Integrity

Memastikan data tidak boleh diubah atau diubah suai semasa dalam perjalanan dari browser ke server tanpa dikesan.

⚠️
Peringatan Penting Untuk Beginner: HTTPS hanya melindungi perjalanan data dalam rangkaian (Data in Transit). Ia TIDAK bermaksud aplikasi anda automatik selamat daripada bug koding, SQL Injection, atau kata laluan lemah!

FASA 4

4. Zero Trust Architecture

💡 Prinsip Teras: "Jangan percaya secara automatik. Sentiasa sahkan (Never Trust, Always Verify)."

Model Tradisional (Perimeter)

"Sesiapa berada dalam rangkaian LAN/VPN dianggap SELAMAT dan dipercayai sepenuhnya."

Jika penceroboh berjaya tembus ke dalam router tempatan, semua server tempatan terdedah.

Model Zero Trust

"Setiap permintaan disemak secara individu: Identiti + Peranti + Konteks Keselamatan."

Walaupun berada dalam rangkaian tempatan yang sama, akses tetap disemak berasaskan polisi ketat.

FASA 5

5. Web Application Firewall (WAF)

Apa Itu WAF?

**WAF (Web Application Firewall)** ialah penapis trafik Layer 7 (HTTP/HTTPS) yang memeriksa setiap permintaan (request) dari Internet sebelum sampai ke aplikasi web anda.

Tujuan Utama WAF

  • Menyekat serangan eksploitasi perisian popular.
  • Menghentikan bot berbahaya dan penapis trafik automatik.
  • Melindungi pelayan daripada beban luar biasa.
🌐 Internet (Trafik Awam)
↓ Send Request
🛡️ Cloudflare WAF (Pemeriksaan Corak Serangan)
❌ Block (Boleh Bahaya) ✅ Pass ➔ Server Local
Modul 14 dari 40 Penapisan Trafik Aplikasi
FASA 5 — WAF

Ancaman Yang Ditangani Oleh WAF

WAF memfokuskan kepada perlindungan defensif terhadap corak serangan umum (OWASP Top 10).

1. SQL Injection (SQLi)

Percubaan menyuntik kod SQL pada borang input untuk mencuri atau memadam pangkalan data.

2. Cross-Site Scripting (XSS)

Suntikan skrip berbahaya yang bertujuan mencuri sesi pengguna lain.

3. Bad Bots & Scrapers

Bot automatik yang mengimbas kelemahan pelayan atau menyalin kandungan secara pukat tunda.

4. Path Traversal

Percubaan membaca fail sistem pelayan (Contoh: ../../etc/passwd).

🛡️ Defensive Focus: WAF Cloudflare mempunyai rule-set terkemaskini secara automatik tanpa perlu anda menulis ribuan skrip sekuriti di backend.

FASA 6

6. Security Rules Custom

Apa Itu Security Rules?

Rule tersendiri yang membolehkan anda menetapkan syarat logik khusus untuk menentukan tindakan ke atas trafik masuk.

Tindakan Utama (Actions):

  • ALLOW: Membenarkan trafik tanpa sekatan.
  • BLOCK: Menyemak & memotong sambungan terus (403).
  • CHALLENGE: Paparkan Turnstile / CAPTCHA interaktif.
  • JS CHALLENGE: Semakan integriti pelayar di latar belakang.

Contoh Senario Rule:

Sekatan Berasaskan Negara

"Jika trafik bukan dari Malaysia/Singapura ➔ CHALLENGE"

Sekatan Reputasi IP

"Jika Threat Score IP > 20 ➔ BLOCK"

Perlindungan Laluan Sensitif

"Jika URI Path mengandungi /wp-admin ➔ ACCESS POLICY"

Modul 17 dari 40 Kawalan Peraturan Trafik
FASA 6 — SECURITY RULES

Logik Peraturan (Pseudocode)

Contoh bagaimana peraturan dibina secara konseptual dalam dashboard keselamatan.

custom_security_rule.rules 
IF (http.request.uri.path eq "/admin") 
   AND (ip.geoip.country ne "MY")
THEN
   ACTION: BLOCK
   // Mesej: Akses Laluan Admin Hanya Dibenarkan Dari Malaysia

IF (http.request.uri.path contains "/api/v1/login") 
   AND (cf.threat_score gt 15)
THEN
   ACTION: MANAGED_CHALLENGE
💡 Prinsip Penting: Jangan terlalu bergantung pada susunan UI spesifik kerana antara muka Cloudflare sentiasa dikemas kini. Fahamkan **konsep logik bertulis** di atas.

FASA 7 — MULTIPLE APPS

Satu Tunnel Daemon, Pelbagai Hostname

Anda TIDAK perlu memasang banyak proses Tunnel. Cuma perlu konfigurasi Ingress Rules.

config.yml (cloudflared Ingress Rules) 
tunnel: <TUNNEL_ID>
credentials-file: /root/.cloudflared/<TUNNEL_ID>.json

ingress:
  - hostname: app.domainbos.com
    service: http://localhost:8080
  - hostname: api.domainbos.com
    service: http://localhost:5000
  - hostname: admin.domainbos.com
    service: http://localhost:3000
  - service: http_status:404

FASA 8 — RASPBERRY PI

Kelebihan & Batasan Raspberry Pi

✅ Kelebihan Utama

  • ✓ Saiz Sangat Kecil: Boleh diletakkan di sebelah router.
  • ✓ Penggunaan Tenaga Rendah: Hanya 5W–15W sahaja.
  • ✓ Boleh Hidup Lama: Stabil berjalan berbulan-bulan tanpa reboot.
  • ✓ Murah Berbanding PC: Penjimatan kos elektrik bulanan yang ketara.
  • ✓ Tempat Belajar Linux Terbaik: Belajar SSH, Docker & systemd.

⚠️ Batasan & Peringatan

  • ⚠️ Prestasi CPU/RAM Terhad: Kurang sesuai untuk pemprosesan video berat.
  • ⚠️ Kad MicroSD Boleh Rosak: Disyorkan guna USB SSD / NVMe.
  • ⚠️ Bukan Untuk Enterprise High-Traffic: Sesuai untuk projek persendirian / kecil.
