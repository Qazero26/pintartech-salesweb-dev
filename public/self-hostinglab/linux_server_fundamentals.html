Apa Itu Linux?

Realiti Utama: Linux = Kernel

Secara teknikal, Linux ialah Kernel — teras perisian yang menguruskan komunikasi antara perkakasan (hardware) dan perisian (software).

Komposisi Sistem Operasi Kompleks:
Linux Kernel
+ System Tools
+ Libraries
+ Package Manager
+ Applications

Elakkan Miskonsepsi

Jangan kata: "Linux = Ubuntu"
Sebaliknya: "Ubuntu ialah sebuah Linux distribution (distro)."
Kernel mengendalikan CPU, RAM, Disk, dan peranti I/O. Distro membungkus kernel tersebut dengan program persekitaran yang sedia digunakan.

Apa Itu Linux Distribution (Distro)?

Distribution / Distro ialah sistem operasi lengkap yang dibina di atas Linux kernel dengan susunan pakej, installer, dan alat pengurusan perisian tersendiri.

Ubuntu

Paling mesra beginner & popular untuk server

Debian

Induk Ubuntu, terkenal dengan kestabilan ultra

Fedora

Inovatif, tajaan Red Hat (RHEL)

Arch Linux

Minimalis, kawalan penuh & rolling release

Rocky Linux

Enterprise grade pengganti CentOS

Untuk siri pembelajaran ini, kita akan fokus menggunakan Ubuntu / Debian sebagai contoh utama command dan konfigurasi.

Kenapa Linux Digunakan Untuk Server?

Stable & Reliable

Boleh berjalan bertahun-tahun tanpa perlu reboot.

Flexible & Light

Tiada GUI membazirkan RAM/CPU server.

Powerful CLI

Kawalan mutlak melalui text command.

Automation

Mudah di-script guna Bash, Python, Ansible.

Large Ecosystem

Majoriti perisian server berasaskan open-source.

Containers

Platform native untuk Docker & Kubernetes.

Remote Admin

Diurus dari jauh secara selamat menggunakan SSH.

Banyak Software

Nginx, Apache, PostgreSQL, Redis sedia ada.

Ingatan PENTING: "Linux bukan automatik secure hanya kerana ia Linux. Keselamatan bergantung kepada cara kita menyelenggara dan mengkonfigurasikannya!"

Membina Folder & Fail

# 1. Cipta folder baharu
$ mkdir myserver
# 2. Masuk ke folder tersebut
$ cd myserver
# 3. Cipta fail kosong 'index.html'
$ touch index.html
# 4. Cipta sub-folder 'logs' dan fail log
$ mkdir logs
$ touch logs/app.log
mkdir = Make Directory (Mencipta folder baharu).
touch = Mencipta fail kosong baharu / mengemaskini timestamp fail.

Copy, Move & Delete

$ cp index.html backup.html # Salin (Copy)
$ mv backup.html old.html # Pindah / Tukar Nama (Move/Rename)
$ rm old.html # Padam Fail (Remove)
$ rmdir logs # Padam Folder Kosong
AMARAN KESELAMATAN PENTING!

Command rm memadam fail secara kekal serta-merta tanpa ada Recycle Bin / Trash Folder!

"Jangan pernah gunakan command 'rm -rf' secara rawak pada server pengeluaran!"

Membaca Fail: cat vs less

cat index.html

Memaparkan keseluruhan kandungan fail ke terminal dalam satu hentakan.

Sesuai untuk: Fail pendek/ringkas.
less index.html

Membuka mod pembaca interaktif. Boleh skrol atas/bawah guna papan kekunci. Tekan 'q' untuk keluar.

Sesuai untuk: Log server & fail teks yang sangat panjang.

Pengguna dalam Linux (Users)

Linux ialah sistem pelbagai pengguna (multi-user OS). Terdapat pelbagai akaun pengguna khas dengan peranan tertentu:

root

Superuser / Administrator dengan hak akses tanpa had.

serveruser

Akaun pengguna biasa untuk tugasan harian pentadbir.

www-data

System user khas yang menjalankan Web Server (Nginx/Apache).

Identiti UID (User ID)
Folder Home Directory
Hak Permissions

Root = Kuasa Penuh

User root boleh melakukan apa sahaja operasi pada sistem termasuk memadam fail sistem teras.

AMALAN BURUK

❌ Login dan membuat semua kerja harian terus menggunakan akaun root. Kesilapan kecil menaip boleh merosakkan seluruh server.

AMALAN TERBAIK (BEST PRACTICE)

✓ Login sebagai Normal User, kemudian gunakan command sudo HANYA apabila memerlukan kebenaran khas.

Apa Itu sudo?

sudo (Superuser Do) membolehkan pengguna biasa yang diberi kebenaran menjalankan command administrative tanpa perlu menukar akaun ke root.

$ sudo apt update
Normal User
sudo Command
Elevated Privilege
System Operation

Kumpulan Pengguna (Groups)

Groups memudahkan pengurusan hak akses untuk sekumpulan pengguna serentak.

User Group (contoh: 'sudo', 'docker') Access Control
# Semak kumpulan yang dianggotai oleh user anda
$ groups
serveruser sudo docker www-data

File Permissions (Kebenaran Akses)

-rwxr-xr--
Owner (rwx)
Read + Write + Execute

Pemilik fail mempunyai kawalan penuh.

Group (r-x)
Read + Execute

Ahli kumpulan boleh membaca & menjalankan fail.

Others (r--)
Read sahaja

Orang awam hanya boleh membaca fail.

r = Read (4)
w = Write (2)
x = Execute (1)

Menukar Permission (chmod)

# Beri kebenaran 'execute' pada fail script
$ chmod +x script.sh
# Jalankan script
$ ./script.sh
AMARAN KESELAMATAN CHMOD 777

Jangan galakkan penggunaan chmod 777 secara sebarangan (ia memberi kebenaran baca/tulis/jalan kepada semua orang di dunia!).

"Gunakan prinsip Least Privilege: berikan permission minimum yang diperlukan sahaja."

Menukar Hak Milik (chown)

Command chown (change owner) digunakan untuk menukar pemilik (user) dan kumpulan (group) bagi sesuatu fail atau direktori.

# Menukar owner & group fail app.log kepada serveruser
$ sudo chown serveruser:serveruser app.log
Kenapa chown penting?

Aplikasi web seperti Nginx (www-data) atau Docker perlukan pemilikan fail yang betul untuk membaca atau menulis fail log/data tanpa ralat "Permission Denied".

Package Manager (APT)

Pada Ubuntu & Debian, APT (Advanced Package Tool) membolehkan pemasangan dan pengurusan perisian dilakukan dengan pantas secara automatik.

$ sudo apt update # Kemaskini senarai pakej
$ sudo apt upgrade # Muat turun & kemaskini versi perisian
$ sudo apt install nginx # Install web server Nginx
Install Apps
Update Software
Remove Apps
Manage Dependencies

apt update vs apt upgrade

sudo apt update

Hanya memuat turun katalog/senarai versi terkini dari repository server. Ia BELUM menukar atau mengemaskini sebarang fail program.

sudo apt upgrade

Sebenar-benarnya memuat turun dan memasang kemaskini perisian sedia ada ke versi terkini berdasarkan katalog apt update.

Langkah yang betul: Sentiasa jalankan apt update terlebih dahulu sebelum apt upgrade!

Services (Perkhidmatan Latar Belakang)

Server menjalankan pelbagai perkhidmatan latar belakang (daemons) yang sentiasa bersedia menerima permintaan.

nginx
Merapatkan web trafik HTTP/HTTPS
ssh
Mengendalikan sambungan kawalan jauh
docker
Mengurus kontena aplikasi
start stop restart enable disable

Mengurus Service dengan systemctl

$ sudo systemctl status nginx # Semak status
$ sudo systemctl start nginx # Mula service
$ sudo systemctl stop nginx # Hentikan service
$ sudo systemctl restart nginx # Reboot service
PERBEZAAN PENTING: start vs enable
start
Mula menjalankan service SEKARANG secara serta-merta.
enable
Mengaktifkan service supaya auto-start setiap kali server reboot.

Kalau Service Bermasalah, Tengok Log (journalctl)

# Semak semua log bagi perkhidmatan Nginx
$ sudo journalctl -u nginx
# Papar 50 baris log yang paling terkini
$ sudo journalctl -u nginx -n 50
# Follow log secara langsung (live output)
$ sudo journalctl -u nginx -f
journalctl membantu anda membaca systemd journal untuk mencari punca error apabila aplikasi gagal bermula.

Linux Firewall (UFW)

Pada Ubuntu, UFW (Uncomplicated Firewall) digunakan untuk mengawal akses masuk dan keluar ke port server.

$ sudo ufw status
$ sudo ufw allow 22/tcp # Benarkan SSH
$ sudo ufw allow 80/tcp # Benarkan HTTP
$ sudo ufw enable # Aktifkan Firewall
AMARAN: Sentiasa benarkan (allow) port SSH (22) TERLEBIH DAHULU sebelum mengaktifkan UFW, jika tidak anda akan terkunci di luar server anda sendiri!

Server Troubleshooting Flow

1. SERVER ALIVE? 2. NETWORK IP? 3. SERVICE RUNNING? 4. PORT LISTENING? 5. FIREWALL OK? 6. READ LOGS!

Situasi Troubleshooting Sebenar

Situasi: "Pelayar web menunjukkan error 'Connection Refused' semasa membuka laman web."
# Command Diagnostik Berperingkat:
$ ip addr # Semak rangkaian
$ ss -tulpn # Semak adakah port 80/443 sedia
$ systemctl status nginx # Semak status web server
$ journalctl -u nginx -n 50 # Semak punca crash
Nasihat Guru: Jangan terus format atau reinstall server. Cari dan selesaikan masalah mengikut lapisan (layer by layer).
