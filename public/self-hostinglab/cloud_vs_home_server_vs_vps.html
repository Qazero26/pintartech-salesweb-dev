Slide 3 • Pengenalan Visual

Tiga Model Infrastructure

Ringkasan titik pemisah fizikal dan tanggungjawab.

Home Server
  • Hardware Kita: Beli & miliki box/server fizikal.
  • Internet Rumah: Menggunakan talian Unifi/Maxis/Time kediaman.
  • Power Rumah: Bergantung bekalan elektrik TNB rumah.
VPS
  • Hardware Provider: Datacenter urus server fizikal & hypervisor.
  • Virtual Server Kita: Kita dapat akses OS Linux tulen (root).
  • Public IP: Talain internet datacenter berpaut terus.
Cloud
  • Provider Infra: Rangkaian global datacenter dengan API.
  • Services Ikut Req: Gunakan API/PaaS/SaaS mengikut keperluan.
  • Elastic Scaling: Tambah/kurang resource berasaskan demand.
Penting: Ketiga-tiga model ini mempunyai kelebihan khusus berdasarkan skala & bajet.
Slide 4 • Deep Dive

Apa Itu Home Server?

Aplikasi server yang dihoskan di premis/rumah sendiri.

Contoh Hardware Popular:

Raspberry Pi 4 / 5
Mini PC (Intel N100/NUC)
Synology / TrueNAS
Desktop/PC terpakai

Aliran Akses Rangkaian Asas:

Internet ➔ Home Router ➔ LAN Switch ➔ Home Server

Integrasi Cloudflare Tunnel

Berkemampuan menyediakan akses awam selamat tanpa mendedahkan IP rumah atau membuat port forwarding inbound pada router!

cloudflared tunnel run my-home-app
*Sangat sesuai untuk homelab dan eksperimen pembangunan perisian.
Kelebihan utama: Kos bulanan perkakasan sifar (setelah dibeli) & privasi fizikal data 100%.
Slide 5 • Deep Dive

Apa Itu VPS?

Virtual Private Server — Potongan virtual pada server fizikal datacenter.

ARCHITECTURE LAYER:
Physical Hardware (Bare Metal Datacenter)
Hypervisor (KVM / Proxmox / ESXi)
VPS Anda (Virtual Machine Instance)
Linux OS ➔ Docker / App Engine

Provider Mengurus:

  • ✔ Bekalan Elektrik & Backup Generator (UPS/Genset)
  • ✔ Penyejukan Datacenter (HVAC Cooling)
  • ✔ Kerosakan Hardware Fizikal (RAM/SSD Rosak)
  • ✔ Talian Network Pipe & Public IP Redundancy

User Mengurus:

  • ⚡ Konfigurasi & Patching OS Linux
  • ⚡ Aplikasi & Kontena Docker
  • ⚡ Keselamatan (Firewall, UFW, SSH Key)
  • ⚡ Backup Data & Disaster Recovery Plan
Akses Root penuh tanpa beban mengurus perkakasan fizikal yang rosak.
Slide 6 • Deep Dive

Apa Itu Cloud?

Cloud bukan sekadar "komputer orang lain", tetapi sebuah ekosistem managed services.

Ekosistem Cloud Moden

Bukan sekadar menyewa VM, tetapi kebolehan memanggil perkhidmatan terurus (Managed Services) melalui API atau Infrastructure as Code (Terraform/Pulumi).

Compute:
Auto-scaling VMs, Serverless Functions
Storage:
S3 Object Storage, Managed NAS
Database:
Managed DB (Postgres/MySQL)
Identity:
IAM, SSO, Secrets Vault

Ciri Asas Cloud Computing:

  • On-Demand Self-Service
  • Broad Network Access
  • Resource Pooling
  • Rapid Elasticity
  • Measured Service (Pay-as-you-go)
Nota: Perbincangan ini fokus secara konseptual dan neutral vendor.
Membolehkan pembinaan sistem berskala tinggi tanpa perlu membina semula roda (reinventing the wheel).
Slide 7 • Model Perkhidmatan

IaaS / PaaS / SaaS

Spektrum kawalan vs pengurusan infrastruktur.

IaaS

Infrastructure as a Service

Sewa VMs, storage & network. Anda install OS, Docker, DB sendiri. (Contoh konsep: VPS/EC2)

Kawalan Tinggi
PaaS

Platform as a Service

Deploy kod/container sahaja. Provider urus OS, scaling & runtime. (Contoh konsep: Managed App Hosting)

Kawalan Sederhana
SaaS

Software as a Service

Guna perisian siap melalui browser/API. Tiada urusan infra langsung.

Kawalan Minimal
Prinsip Utama: Semakin ke bawah (SaaS), semakin kurang beban pengurusan infrastruktur tetapi semakin berkurang kawalan granular.
Slide 8 • Pemilikan

Infrastructure Ownership

Siapa sebenar pemilik aset fizikal & perisian anda?

HOME SERVER

Hardware Fizikal: Kita 100% (Milik kekal).

Akses Fizikal: Boleh sentuh, tukar RAM, cabut HDD secara manual bila-bila masa.

Lokasi Data: Berada dalam premis sendiri.

VPS

Hardware Fizikal: Hak milik Datacenter Provider.

Virtual Space: Diuji & diperuntukkan secara digital kepada kita.

Akses Fizikal: Tiada. Hanya melalui SSH / VNC Console.

CLOUD

Infrastructure: Hak milik eksklusif Cloud Vendor.

Resource Lease: Menyewa kapabiliti melalui API/Portal.

Akses: Dikawal ketat oleh API Tokens, IAM Policies, & SDK.

Pemilikan menentukan hak mutlak terhadap perkakasan semasa berlaku kecemasan atau muflis provider.

Slide 10 • Model Kewangan

CAPEX vs OPEX

Bagaimana bajet organisasi & individu diperuntukkan.

CAPEX (Capital Expenditure)

Pelaburan modal pendahuluan. Beli barang di awal.

• Raspberry Pi + Case: RM 450

• NVMe SSD 1TB: RM 350

• Mini PC / Server: RM 1,500

• UPS Battery Backup: RM 250

Tinggi di awal, tetapi kos berjalan bulanan minimum.

OPEX (Operational Expenditure)

Kos operasi berterusan mengikut langganan / guna.

• VPS Monthly Plan: RM 30/bulan

• Managed Cloud DB: RM 120/bulan

• Cloud Egress Bandwidth: Ikut GB

• Object Storage S3: Ikut Usage

Rendah di awal, tetapi komitmen berkala berterusan.

Home Server = High Upfront CAPEX | VPS & Cloud = Ongoing OPEX Model.

Slide 12 • Kos Tersembunyi

Hidden Costs

Perbelanjaan yang kerap terlepas pandang semasa perancangan awal.

Home Server Hidden Cost

  • • Bil elektrik tambahan (30W-100W)
  • • Bateri UPS rosak selepas 2 tahun
  • • Masa troubleshooting anda (Admin hours)
  • • Downtime semasa anda bercuti

VPS Hidden Cost

  • • Backup snapshots tambahan
  • • Extra IP address ($2-$5/mo)
  • • Upgrade plan sebab RAM tak cukup
  • • Masa patching OS manual

Cloud Hidden Cost

  • • Egress Data Transfer Fee (Sangat Mahal!)
  • • CloudWatch / Log retention cost
  • • NAT Gateway hourly charges
  • • Complexity overhead & misconfiguration

"Kos sebenar bukan sekadar angka pada resit atau invoice."

Sentiasa masukkan elemen 'Admin Time Value' dalam pengiraan TCO.
Slide 13 • Prestasi

Performance Considerations

Prestasi tidak hanya bergantung pada bilangan core CPU.

HOME SERVER

Bergantung 100% pada hardware dipasang + kelajuan upload internet rumah (e.g. Unifi 100Mbps = ~50Mbps Upload).

LAN: 1Gbps / WAN: Limited

VPS

Shared CPU vCPU / Contention Ratio. Boleh terjejas jika ada "noisy neighbour" pada hypervisor fizikal yang sama.

Shared vCPU / Dedicated vCPU

CLOUD

Pilihan sangat fleksibel daripada T-series kecil hingga GPU Specialized instance & Dedicated Compute Clusters.

High IOPS & Scalable Network

Kesimpulan Prestasi: "Sentiasa jalankan benchmark pada workload sebenar, bukan sekadar angka spec bertulis."

Disk IOPS & Latency Rangkaian kerap menjadi bottleneck berbanding CPU.
Slide 14 • Rangkaian

Network Connectivity

Bagaimana trafik sampai ke server anda dari seluruh dunia.

Home Server Topology:

Internet ➔ ISP Network ➔ Carrier Grade NAT (CGNAT) ➔ Home Router ➔ Local Server

Cabaran: Dynamic IP, CGNAT mendedahkan kesukaran port forwarding, restriction port 80/443 dari ISP.

VPS Topology:

Internet ➔ Datacenter Edge Router ➔ Static IPv4/IPv6 ➔ VPS Virtual Interface

Kelebihan: Public IP kekal, bandwidth tinggi (1Gbps+), tiada Sekatan ISP biasa.

Cloud Topology:

Internet ➔ Global CDN / Edge ➔ Anycast IP ➔ Load Balancer ➔ VPC Private Subnet Instance

Kelebihan: Rangkaian selamat berasingan (VPC) & perlindungan DDoS terbina.

Ketersambungan rangkaian menentukan sejauh mana aplikasi anda mudah diakses oleh pengguna luar.
Slide 15 • Akses Awam

Public Access Strategy

Kaedah pendedahan perkhidmatan kepada pengguna awam.

Pilihan Home Server:

Option A: Direct Public IP + DDNS

Buka Port Forwarding (80/443) pada Router. Risiko keselamatan tinggi jika router digodam!

Option B: Cloudflare Tunnel (Disyorkan)

Sambungan outbound selamat. Tiada port dibuka pada router kediaman.

Pilihan VPS & Cloud:

VPS Direct Access:

Public IP diberikan automatik. Lindungi guna UFW Firewall & Fail2Ban.

Cloud Managed Entry:

Akses melalui Application Load Balancer (ALB) & Cloud WAF untuk menyaring trafik jahat.

Jangan sesekali mendedahkan port SSH (22) atau Database (5432) terus ke internet awam tanpa tapisan.

Slide 17 • Ketersediaan

Availability Realities

Apa berlaku apabila komponen mengalami kerosakan?

HOME SERVER

Risiko Tinggi: Potongan elektrik TNB, router hang, kucing terlanggar plug, Unifi down, suhu panas tanpa ekor penghawa dingin.

Uptime: ~95% - 98%

VPS

Sederhana-Tinggi: Datacenter punyai Dual Power Feed, Diesel Generator Backup, redundant cooling, & multiple Tier-1 ISPs.

SLA: ~99.9%

CLOUD

Sangat Tinggi: Kebolehan Multi-Availability Zone (Multi-AZ) & Region failover automatik jika dirancang dengan betul.

SLA: 99.99% - 99.999%
Ketersediaan (Availability) diukur dalam bilangan '9' (Nines of Availability).
Slide 18 • Titik Kegagalan

Single Point of Failure (SPOF)

Menganalisis punca utama sesebuah sistem terhenti secara tiba-tiba.

SPOF dalam Home Server:

  • ⚠️ 1x Raspberry Pi (Board rosak)
  • ⚠️ 1x SD Card / Micro SSD (Corrupt)
  • ⚠️ 1x Internet Router Kediaman
  • ⚠️ 1x Bekalan Elektrik Utama Rumah
Terdapat BANYAK titik kegagalan tunggal!

SPOF dalam VPS & Cloud:

  • ⚠️ Single VPS Instance crash / Kernel panic
  • ⚠️ Misconfiguration pada Nginx / Cloudflare DNS
  • ⚠️ Provider Outage (Sangat jarang berlaku tapi ada)
Kurang isu hardware, tetapi isu perisian & konfigurasi kekal.
Matlamat jurutera binaan: Hapuskan SPOF sejauh mana bajet mengizinkan.
Slide 19 • Redundansi

Redundancy Architecture

Membina sistem bertindan untuk memastikan kelangsungan perkhidmatan.

Home Server Redundancy

• Beli UPS Battery Backup

• Pasang Dual WAN Router (Unifi + 4G/5G Dongle)

• RAID 1 / ZFS Mirror Storage

*Kos & kompleksiti fizikal meningkat di rumah.

VPS Redundancy

• Sewa 2x VPS di Datacenter berbeza

• Setup DNS Round Robin / Cloudflare Load Balancer

• Database Master-Replica Sync

Cloud Redundancy

• Managed Auto-Scaling Group

• Multi-AZ Managed PostgreSQL

• Serverless Multi-Region failover

📌 Hukum Redundansi: Redundansi menambah ketersediaan, tetapi secara langsung MENGAPUNGKAN kos dan kompleksiti operasi.
Ketahui bila redundansi benar-benar diperlukan vs bila perkhidmatan boleh bertoleransi dengan downtime sementara.
Slide 20 • Skala

Scaling Fundamentals

Bagaimana infrastruktur bertindak balas apabila pengguna melonjak mendadak.

HOME SERVER SCALING

Sangat terhad. Jika Raspberry Pi tidak cukup RAM, anda perlu beli PC baharu atau tambah Pi dalam Cluster (K3s). Bandwidth upload rumah menjadi kemuncak halangan utama (bottleneck).

VPS SCALING

Pantas tetapi perlu reboot. Anda boleh 'Resize' plan dari 2 vCPU ke 8 vCPU dalam beberapa minit melalui dashboard provider.

CLOUD SCALING

Hampir tanpa had (Elastic). Auto-scaler menambah instance baru secara automatik dalam masa beberapa saat berdasarkan penggunaan CPU/Memory.

Keupayaan menaikkan skala tanpa ganguan perkhidmatan adalah kelebihan terbesar Cloud Computing.
Slide 21 • Jenis Skala

Vertical vs Horizontal Scaling

Memahami strategi pembesaran kapasiti sistem.

Scale UP (Vertical)

Menambah kekuatan pada SATU server sedia ada (Tukar CPU lebih laju, tambah RAM dari 8GB ke 64GB).

Server A (4GB) ➔ Upgrade ➔ Server A (32GB)

✔ Sangat MUDAH, tiada perubahan pada seni bina aplikasi.

✖ Ada had maksimum fizikal & kos menjadi sangat mahal di kemuncak.

Scale OUT (Horizontal)

Menambah BILANGAN server selari di belakang Load Balancer.

Load Balancer ➔ [Server 1, Server 2, Server 3]

✔ Skala tanpa had & tinggi ketahanan (Fault Tolerant).

✖ KOMPLEKS. Memerlukan Stateless App & Distributed Database.

Aplikasi monolitik biasanya bermula dengan Vertical Scaling sebelum bertukar ke Horizontal.
Slide 22 • Storan

Storage Architecture

Perbezaan jenis & kaedah pengurusan storan data.

HOME SERVER STORAGE

  • • NVMe / SATA SSD Terus pada board
  • • Hard Disk HDD 3.5" dalam NAS / RAID
  • • USB External Drive (Kurang disyorkan)

Kita bertanggungjawab penuh atas RAID degrade & replacement.

VPS STORAGE

  • • Local NVMe Block Storage (Pantas)
  • • Cloud Network Attached Volume
  • • Fleksibel untuk resize secara digital

Provider urus kerosakan fizikal pemacu SSD.

CLOUD STORAGE SPECTRUM

  • • Block Storage: Virtual SSD untuk OS
  • • Object Storage: S3 Bucket untuk gambar/media
  • • File Storage: Shared NFS / EFS

S3 Object Storage pilihan terhebat untuk kos media terendah.

Memisahkan fail media statik ke Object Storage mengurangkan kos storan server secara drastik.

Slide 24 • Pemulihan Bencana

Disaster Recovery (DR)

Langkah pemulihan apabila bencana total berlaku.

Home Server DR Flow

Server Rosak ➔ Beli Hardware Baru ➔ Reinstall OS Linux ➔ Deploy Docker ➔ Restore DB & Data (Masa: 4-24 Jam)

VPS DR Flow

VPS Corrupt ➔ Spin Up New VPS ➔ Run Ansible Script / Docker Compose ➔ Restore DB (Masa: 30-60 Minit)

Cloud DR Flow

Region Down ➔ Terraform Auto-Provision di Region B ➔ Failover Route53 DNS (Masa: Saat ke Minit)

RTO (Recovery Time Objective): Berapa lama masa terhenti yang boleh ditoleransi?
RPO (Recovery Point Objective): Berapa banyak data yang sanggup hilang?
RTO & RPO menentukan struktur kos pemulihan bencana anda.
Slide 25 • Keselamatan

Security Responsibility

Siapa yang bertanggunjawab mempertahankan kubu keselamatan?

HOME SERVER SECURITY

100% Tanggungjawab Anda: Secure Router, Wi-Fi Password, Isolation IoT VLAN, OS Firewall (UFW), SSH Keys, Fail2Ban, & Physical Intrusion.

VPS SECURITY

Shared Boundary: Provider pertahan Physical Datacenter & Hypervisor. Anda pertahan OS Kernel, Port Firewall, Application vulnerabilities, & SSL.

CLOUD SHARED MODEL

Security OF the Cloud vs IN the Cloud: Vendor jaga infra fizikal & hypervisor. Anda wajib urus IAM Permissions, Encryption Keys, & Network Rules.

Kecuaian menguruskan IAM Credentials di Cloud kerap menjadi punca utama kebocoran data terluar.
Slide 26 • Beban Pentadbiran

Management Burden

Berapa banyak tenaga & masa yang perlu diperuntukkan?

HIGH 🔥

HOME SERVER

Menjaga hardware, habuk, kepanasan, router reboot, OS patch, & masalah fizikal.

MEDIUM 🟡

VPS

Bebas dari hardware. Fokus pada OS Linux Updates, Docker maintenance, & App deployment.

LOWER 🟢

CLOUD MANAGED

More Abstraction = Less Infrastructure Management Overhead.
Slide 27 • Trade-off Konseptual

Control vs Convenience

Kompromi utama dalam pembuatan keputusan infrastruktur.

KAWALAN MAKSIMUM (Control) KEMUDAHAN MAKSIMUM (Convenience)
Home Server / Bare Metal

Akses hardware penuh, custom kernel, tiada sebarang sekatan provider.

VPS (Linux Instance)

Akses Root OS, kawalan software penuh tetapi hardware dikawal virtualizer.

Cloud Managed / Serverless

Zero OS management, instant scale, tetapi terikat pada ekosistem vendor.

Tiada pilihan terbaik mutlak. Hanya trade-off yang sesuai dengan sasaran anda.
Slide 28 • Kedaulatan Data

Data Sovereignty & Privacy

Di mana lokasi fizikal data anda berada dan undang-undang yang terpakai?

Home Server

Data secara fizikal berada dalam premis anda di Malaysia. Zero third-party datamining or subpoena risk tanpa waran tempatan.

VPS

Bergantung kepada wilayah Datacenter pilihan (e.g. Singapore / US / EU). Terikat dengan undang-undang privasi negara terbabit (e.g. GDPR / US CLOUD Act).

Cloud Multi-Region

Data boleh direplikasi merentasi pelbagai region global. Memerlukan kepatuhan piawaian perundangan data ketat (PDPA Malaysia / ISO27001).

Sangat penting untuk sektor kewangan, kesihatan, & perkhidmatan awam.
Slide 29 • Kebergantungan Rangkaian

Internet Dependency

Bagaimana kestabilan talian internet mempengaruhi perkhidmatan.

Jika ISP Rumah Terputus (Unifi Down):

🔴 Semua perkhidmatan awam yang dihoskan di Home Server TERPUTUS serta-merta bagi pengguna luar!

(Tetapi aplikasi local LAN rumah masih berfungsi jika dipanggil terus guna IP Tempatan).

Jika Datacenter ISP Terputus:

🟡 Amat jarang berlaku kerana Datacenter punyai redundant BGP Fiber Routes dari pelbagai telco utama.

Kesimpulan: "Tiada sebarang seni bina yang benar-benar bebas daripada kebergantungan rangkaian (Network Dependency)."
Rangkaian ialah urat saraf utama bagi mana-mana deployment pelayan.
Slide 30 • Latensi

Latency Analysis

Kelajuan tindak balas paket data (Ping Time in ms).

Akses Pengguna Dalam Rumah (LAN):

Pengguna Rumah ➔ Home Server < 1 ms (Ultra-Fast)

Paling sesuai untuk Home Automation, Media Streaming (Jellyfin/Plex 4K Local), & Smart Home IoT.

Akses Pengguna Luar / Awam (WAN):

Pengguna KL ➔ Datacenter SG VPS 10 - 25 ms
Pengguna KL ➔ Home Server (via Cloudflare) 30 - 60 ms

Datacenter / Cloud Edge memberikan latensi paling stabil untuk trafik luar.

Jarak fizikal server ke pengguna adalah faktor terbesar yang menentukan latensi.
Slide 31 • Permukaan Serangan

Security of Home Network

Risiko mendedahkan rangkaian kediaman ke internet.

Attack Surface Rangkaian Rumah Mengandungi:

Wi-Fi Kediaman
IoT Smart Devices
PC Laptop Ahli Keluarga
Home Server Anda

Jika Home Server anda pencerobohan berlaku disebabkan misconfiguration, penggodam boleh merayap (Lateral Movement) ke dalam peranti IoT atau laptop peribadi ahli keluarga dalam subnet yang sama!

💡 Mitigasi Wajib: Asingkan Home Server ke dalam VLAN khas (Isolated Network Subnet) dan elakkan pendedahan port terus tanpa Cloudflare Tunnel / VPN.
Keselamatan rangkaian rumah memerlukan pengasingan (Network Segmentation) yang berdisiplin.

Slide 33 • Penyelenggaraan

Maintenance Requirements

Tugas berkala untuk memastikan pelayan kekal relevan dan selamat.

Penyelenggaraan Home Server:

  • 🧹 Bersihkan habuk fizikal & tukar Thermal Paste
  • 🔋 Uji ketahanan bateri UPS
  • 🔄 Kemaskini OS Linux (`apt update && apt upgrade`)
  • 📦 Kemaskini Docker Containers (Watchtower / Manual)
  • 📡 Semak log penapis router & Cloudflare tunnel

Penyelenggaraan VPS & Cloud:

  • 🛡️ Terapkan Security Patches pada Kernel Linux
  • 🧹 Padam Unused Docker Images (`docker system prune`)
  • 🔑 Rotate SSH Keys & API Secrets secara berkala
  • 💳 Semak penggunaan bil & elak kebocoran kuota
  • 📋 Auditing fail log kejanggalan trafik
Penyelenggaraan berdisiplin mengelakkan kejadian krisis kecemasan di kemudian hari.

Slide 42 • Bila Menang?

When Home Server Wins

Situasi di mana Home Server menjadi pilihan yang terbaik.

Pilih Home Server Jika:
  • Anda mahu belajar Linux, Networking, & Docker secara hands-on dari asas.
  • Mahukan kawalan mutlak ke atas data fizikal & privasi peribadi.
  • Workload bersifat tempatan (Smart Home, Local Storage, LAN Media).
  • Sanggup menjaga hardware dan mematuhi risiko ketersediaan sederhana.
  • Mempunyai storan data bersaiz Terabytes yang mahal jika disimpan di Cloud.
Kemenangan utama: Kos storan per-Gigabyte termurah & nilai pembelajaran tertinggi.
Slide 43 • Bila Menang?

When VPS Wins

Situasi di mana VPS menjadi pilihan paling manis.

Pilih VPS Jika:
  • Mahukan pelayan awam dengan IP Statik tanpa beban urus hardware.
  • Perlukan bil kos bulanan yang TETAP & Ramah Bajet (Predictable Pricing).
  • Aplikasi memerlukan akses OS Linux penuh (Root Access).
  • Workload kecil hingga sederhana (Blog, API, Small Business Site).
  • Mahukan rangkaian datacenter yang pantas dan stabil 24/7.
Kemenangan utama: Keseimbangan sempurna antara harga tetap & kestabilan awam.
Slide 44 • Bila Menang?

When Cloud Wins

Situasi di mana Cloud berkuasa mutlak.

Pilih Cloud Jika:
  • Perlukan Managed Databases (Postgres, Redis) dengan automated failover.
  • Trafik aplikasi bersifat tidak menentu & perlukan Auto-Scaling automatik.
  • Membina sistem berskala besar dengan pasukan jurutera perisian.
  • Memerlukan ekosistem perkhidmatan lengkap (IAM, Serverless, CDN, S3).
  • Bajet perniagaan mencukupi untuk membayar kemudahan pengurusan.
Kemenangan utama: Elastic Scaling, Managed Services, & Enterprise Reliability.
Slide 45 • Bila Elakkan?

When Home Server is a BAD Idea

Situasi di mana menggunakan Home Server adalah kesilapan besar.

ELAKKAN Home Server Jika:
  • ❌ Critical Business Workload: Sistem e-commerce / payment gateway perniagaan.
  • ❌ Strict Uptime SLA: Pengguna mengecam jika terhenti walau 5 minit.
  • ❌ Talian Internet Rumah Tidak Stabil: Tiada backup WAN / Sering terputus.
  • ❌ Tiada Masa Maintenance: Anda sibuk & tiada masa baiki jika hardware rosak.
  • ❌ Tiada Keupayaan Keselamatan: Mendedahkan port rumah tanpa ilmu penapisan.
"Masalah bukan pada Raspberry Pi. Masalah ialah mismatch dengan requirement."
Padankan tahap toleransi kegagalan perniagaan anda dengan lokasi infrastruktur.
Slide 46 • Bila Elakkan?

When VPS is a BAD Idea

Situasi di mana VPS kurang sesuai.

ELAKKAN VPS Jika:
  • ❌ Perlukan GPU Heavy Workload (Sangat mahal pada VPS biasa).
  • ❌ Memerlukan kawalan fizikal terus pada perkakasan server.
  • ❌ Memerlukan storan data saiz gergasi (10TB+) dengan kos bajet terhad.
  • ❌ Mahukan Managed Failover automatik tanpa perlu setup manual.
Kenal pasti kekangan VPS sebelum komit jangka panjang.
Slide 47 • Bila Elakkan?

When Cloud is a BAD Idea

Situasi di mana Cloud bertukar menjadi perangkap kos & overengineering.

ELAKKAN Cloud Jika:
  • ❌ Workload Terlalu Simple: Hanya blog statik atau API kecil yang tidak berubah.
  • ❌ Fixed Low Traffic: Trafik stabil 100 pelawat sehari (VPS $5 dah memadai).
  • ❌ Tiada Pengalaman Pentadbiran Cloud: Berisiko menyebabkan kebankrapan bil!
  • ❌ Overengineering: Menggunakan Kubernetes + Microservices untuk aplikasi mudah.
💡 Cloud boleh menjadi perangkap Overengineering jika bajet & kemahiran tidak sepadan.
Jangan gunakan bazooka untuk menembak nyamuk.
Slide 48 • TCO Formula

Total Cost of Ownership (TCO)

Formula sebenar menilai jumlah kos pelaburan infrastruktur.

TCO = Direct Expenses + Hidden Expenses + Admin Time Value
Home Server TCO:

Hardware + UPS + TNB Electricity + Replacement Parts + Your Time

VPS TCO:

Subscription Fee + Storage Extensions + OS Patching Time

Cloud TCO:

Resource Usage + Egress Bandwidth + Cloud Cert Engineers' Salaries

Menilai TCO memberikan pandangan holistik 3-5 tahun berbanding menilai sebulan.
Slide 49 • Masa Pentadbir

Admin Time Value

Kos tersembunyi yang paling mahal: Masa Nyawa Anda!

"Berapa jam seminggu anda habiskan untuk maintain server?"

Home Server:

3-6 Jam / Minggu (Troubleshoot hardware, router, DNS, cooling, backups).

VPS:

1-2 Jam / Minggu (Linux updates, app deployment, basic logs).

Cloud Managed:

0.5-1 Jam / Minggu (Fokus terus pada application code & features!).

💡 Jika nilai masa anda ialah RM50/jam, 5 jam seminggu = RM1,000/bulan "Admin Cost"!
Pilih infrastruktur yang tidak mencuri masa lapang hujung minggu anda.
Slide 50 • Vendor Lock-in

Vendor Lock-in Risk

Risiko terperangkap dalam ekosistem pembekal tertentu.

HOME SERVER

Lock-in Rendah (0%): Kod & Docker image berjalan pada hardware fizikal anda. Boleh dipindahkan ke mana-mana server Linux bila-bila masa.

VPS

Lock-in Sederhana (10%): Hanya terikat dengan IP Address. Sangat mudah pusing ke VPS provider lain menggunakan rsync / Docker.

CLOUD MANAGED

Lock-in Tinggi (60%-90%): Penggunaan proprietary APIs (DynamoDB, BigQuery, Serverless triggers) membuatkan migrasi keluar sangat sukar & mahal!

Gunakan Docker & Open Standards untuk meminimumkan Vendor Lock-in.

Slide 52 • Alur Migrasi

Migration Strategy

Langkah selamat memindahkan aplikasi dari Home Server ke VPS/Cloud.

1
Provision VPS Baru: Sediakan OS Linux bersih, setup SSH Keys & Firewall.
2
Deploy Container: Pindahkan `docker-compose.yml` & konfigurasikan `.env`.
3
Sync Data: Eksport Database (`pg_dump`) & Pindahkan fail guna `rsync`.
4
DNS Switch: Kemaskini rekod DNS Cloudflare ke Public IP VPS baharu.
Migrasi bukan kegagalan, tetapi tanda perkhidmatan anda sedang berkembang!

Slide 62 • Senario 1

Scenario 1: Belajar Docker & Linux

Pelajar mahu menguasai perintah Docker, Linux Kernel, & Networking.

Cadangan Utama: HOME SERVER (Raspberry Pi / Old PC)

Kenapa? Kos sifar sewaan bulanan. Bebas merosakkan OS (break & fix), install/reinstall berulang kali tanpa rasa takut caj tersembunyi. Belajar memasang SSD, kabel LAN, dan penetapan IP tempatan.

Slide 63 • Senario 2

Scenario 2: Small Public API 24/7

Cadangan Permulaan: VPS (RM 20-40 / bulan)

Kenapa? Memerlukan Public IP statik dan ketersediaan talian datacenter 24/7 tanpa risiko terputus elektrik rumah. Kos bulanan sangat tetap dan terjangkau untuk perniagaan kecil.

✔ Keputusan Terbaik: VPS!
Aplikasi awam berkeperluan asas mendapat manfaat terbesar dari VPS.
Slide 64 • Senario 3

Scenario 3: Managed PostgreSQL + CDN

Aplikasi yang memerlukan Managed Database terurus & media CDN.

Cadangan Utama: CLOUD

Kenapa? Menguruskan failover PostgreSQL secara manual di VPS/Home Server amat sukar. Managed Cloud DB menyediakan failover automatik & automated Point-in-Time Restore (PITR).

✔ Keputusan Terbaik: Cloud Provider!
Memindahkan risiko pengurusan database kepada pihak penyedia perkhidmatan.
Slide 65 • Senario 4

Scenario 4: Home Automation & NAS

Sistem kawalan rumah pintar & simpanan fail keluarga.

Cadangan Mutlak: HOME SERVER

Kenapa? Latensi tempatan (LAN) bawah 1ms. Jika internet rumah terputus, suis lampu & sensor smart home tetap berfungsi! Data fail peribadi tidak dihantar ke server pihak ketiga.

✔ Keputusan Terbaik: Home Server Mutlak!
Privasi dan kestabilan LAN tidak dapat ditandingi oleh mana-mana Cloud.
Slide 66 • Senario 5

Scenario 5: Lonjakan Trafik (100 ➔ 100k Users)

Slide 78 • Kesilapan Lazim

Common Pitfalls & Mistakes

Jauhi kesilapan biasa yang kerap dilakukan oleh pemula.

❌ Guna Cloud untuk workload terlalu simple (Overspending).
❌ Guna Pi untuk critical business tanpa redundancy.
❌ Sewa VPS tanpa sebarang strategi automated backup.
❌ Anggap Cloud automatik secure tanpa konfigurasi IAM.
❌ Mengabaikan nilai masa nyawa sendiri (Admin Time).
❌ Pilih platform sebab Hype semasa di media sosial.
Belajar dari kesilapan orang lain mengelakkan kerugian masa dan duit anda.
