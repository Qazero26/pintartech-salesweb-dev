Kekurangan Cara Ini

  • Pengguna perlu ingat Nombor Port: Sangat mesra pengguna yang lemah.
  • URL Tidak Buruk/Cantik: Penggunaan nombor port merosakkan branding URL.
  • HTTPS Rumit: Setiap nombor port perlu sijil SSL/TLS secara berasingan.
  • Risiko Keselamatan: Membuka banyak port terus ke Internet awam.

Definisi Utama

Apa itu Reverse Proxy?

WHAT

Definisi Mudah

"Reverse proxy ialah server perantara yang menerima incoming request daripada client di Internet dan meneruskannya (forward) kepada backend server yang sesuai di dalam rangkaian dalaman."
"Front Door"

Bertindak sebagai pintu masuk utama yang mengurus semua lalulintas masuk bagi pihak application.

Pelindung Backend

Client luar tidak pernah berhubung secara terus dengan backend application sebenar.

Penyusun Lalu Lintas

Menentukan hala tuju paket berdasarkan maklumat domain, path, atau header.

Etimologi Rangkaian

Kenapa Nama "Reverse"?

Forward Proxy (Standard Proxy)

Bertindak bagi pihak CLIENT (Pengguna).

Client (Laptop Anda)
↓
[ Forward Proxy ]
↓
Internet / Server Luar

Server luar tidak tahu IP sebenar Client.

Reverse Proxy

Bertindak di hadapan SERVER (Backend).

Client (Awam)
↓
[ Reverse Proxy ]
↓
Backend Application Internal

Client tidak tahu IP / Port sebenar Backend Server.

Perbandingan Matrik

Forward Proxy vs Reverse Proxy

Ciri-Ciri Forward Proxy Reverse Proxy
Mewakili Siapa? Client (Pengguna Dalaman) Server (Backend Infrastructure)
Kedudukan Di hadapan Client Di hadapan Server
Tujuan Utama Bypass firewall, Privacy client, Content filtering corporate Routing hostname, TLS termination, Load balancing, Security
Siapa Tahu Kewujudannya? Client tahu (perlu setup proxy setting) Client TIDAK TAHU (Lutsinar / Transparent)

Konsep Utama Routing

Hostname Routing

Hostname Routing ialah kebolehan Reverse Proxy membaca nama domain yang diminta oleh pelayar web (cth: `app1.example.com`) dan menghantarnya ke lokasi backend yang khusus.

Request A:
app1.example.com
↓ Proxy Decision
Forward to http://127.0.0.1:8001
Request B:
app2.example.com
↓ Proxy Decision
Forward to http://127.0.0.1:8002
Logik Keputusan

Hostname Routing Logic

Pseudocode Keputusan Proxy:
IF Request.Host == "app1.example.com" THEN
    Proxy_Pass → http://localhost:8081

ELSE IF Request.Host == "app2.example.com" THEN
    Proxy_Pass → http://localhost:8082

ELSE IF Request.Host == "api.example.com" THEN
    Proxy_Pass → http://localhost:5000

ELSE
    Return HTTP 404 (Not Found) / Default Page
END IF
Nota Kunci: Reverse Proxy mengetahui domain mana yang diminta dengan memeriksa HTTP Host Header dalam paket data TCP HTTP.
Routing Sub-path

Path Routing

Selain menggunakan subdomain yang berbeza, Reverse Proxy juga boleh membuat routing berdasarkan URL Path (Subpath) pada domain yang sama.

example.com/app1
↓
App 1 (:8081)
example.com/app2
↓
App 2 (:8082)
example.com/api
↓
API (:5000)
Perbandingan

Hostname Routing vs Path Routing

HOSTNAME ROUTING

app1.example.com, app2.example.com
  • Kelebihan: Pengasingan bersih, aplikasi tidak perlu konfigurasi base path khusus.
  • Sangat sesuai untuk pelbagai aplikasi berbeza.
  • Memerlukan pengurusan DNS A/CNAME/Wildcard record.

PATH ROUTING

example.com/app1, example.com/app2
  • Kelebihan: Cuma perlu 1 nama domain & 1 rekod DNS.
  • Cabaran: Aset HTML/JS/CSS dalam aplikasi (relative URL) kerap rosak jika app tidak menyokong subpath base URL.

Perbezaan Peranan

Web Server vs Reverse Proxy

WEB SERVER

Menyajikan fail fizikal terus dari storan server (Disk Storage).

HTML, CSS, JS, Gambar, Video

REVERSE PROXY

Menerima request dan meneruskannya (forward) kepada proses / server lain.

Node.js, Python Flask, Java Spring
PENTING: Perisian modern seperti NGINX dan Caddy boleh menjalankan kedua-dua peranan ini serentak dalam satu perisian!
Perisian Popular

NGINX

NGINX (sebutan: "Engine-X") ialah web server dan reverse proxy berprestasi tinggi yang memproses peratusan besar trafik web dunia.

  • Sangat pantas dan menggunakan RAM rendah.
  • Menyokong Caching, Load Balancing & TLS Termination.
  • Standard industri untuk production deployment.
NGINX Architecture
Worker Processes (Asynchronous Event-Driven)
Contoh Konfigurasi

NGINX Configuration Concept

nginx.conf (Contoh Pembelajaran) 
server {
    listen 80;
    server_name app.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}

listen 80: Mendengar trafik pada Port HTTP 80.

server_name: Memadankan HTTP Host header `app.example.com`.

proxy_pass: Meneruskan paket ke server internal `:8080`.

Perisian Moden

Caddy Server

Caddy ialah web server / reverse proxy generasi moden yang ditulis dalam bahasa Go. Ciri paling popularnya ialah Automatic HTTPS secara binaan (built-in Let's Encrypt).

Caddyfile (Simple & Clean):
app.example.com {
    reverse_proxy localhost:8080
}

Kelebihan Caddy:

  • Automatik HTTPS tanpa perlu install Certbot terpisah.
  • Sintaks konfigurasi mudah difahami beginner.
  • Memproses SSL renewal di background secara automatik.
Analisis Pemilihan

NGINX vs Caddy

NGINX

  • Sangat matang & diuji dalam persekitaran Enterprise.
  • Ekosistem komuniti terbesar.
  • Sangat Fleksibel & High Performance.
  • Perlu persediaan Certbot/SSL manual.

CADDY

  • Sintaks konfigurasi minimalis.
  • Automatic HTTPS out-of-the-box.
  • Mesra pengguna Self-Hosting / Home Server.
  • Prestasi cemerlang untuk kebanyakan kegunaan.
"Tiada satu pilihan yang sentiasa terbaik — pilih mengikut keperluan dan kompleksiti seni bina anda."

Mekanisme Dalaman

HTTP Host Header

Apabila pelayar web membuat request HTTP, ia menyertakan maklumat domain dalam HTTP Header bernama Host.

GET /index.html HTTP/1.1
Host: app.example.com
User-Agent: Mozilla/5.0...

Bukan "Magic"!

Reverse Proxy membaca baris Host: app.example.com ini untuk memadankan lokasi backend yang betul.

Pemeliharaan Konteks

HTTP Headers Forwarding

Apabila Reverse Proxy meneruskan request ke backend, backend secara lalai hanya nampak IP Reverse Proxy. Untuk mengekalkan data asal pengguna, header khas dihantar:

Host
Domain asal yang di-request oleh client.
X-Forwarded-For
IP Address asal pengguna (Client IP).
X-Forwarded-Proto
Protokol asal (http atau https).
X-Real-IP
IP sebenar client tanpa rantai proxy.
Identiti Pengguna

X-Forwarded-For Header

Client IP: 203.0.113.50
→
Proxy IP: 192.168.1.50
→
Backend App
X-Forwarded-For: 203.0.113.50
AMARAN KESELAMATAN:

Jangan mempercayai header X-Forwarded-For secara membuta tuli dari Internet awam jika Reverse Proxy anda tidak dikonfigurasi untuk membuang header palsu yang disuntik penggodam!

Kesedaran Protokol

X-Forwarded-Proto Header

Client berkomunikasi dengan Reverse Proxy menggunakan HTTPS. Namun Reverse Proxy berkomunikasi dengan backend menggunakan HTTP biasa.

Backend memerlukan header ini untuk:

  • Menjana URL redirect selamat (`https://`).
  • Menaikkan `Secure` flag pada Cookie pengguna.
Client ↔ Proxy: HTTPS
Proxy ↔ Backend: HTTP
X-Forwarded-Proto: https
Penyahkodan SSL

TLS Termination

WHAT

Apa itu TLS Termination?

Proses di mana enkripsi SSL/TLS dinyahkodkan (decrypt) di tahap Reverse Proxy, membolehkan trafik ke backend dijalankan secara HTTP biasa dalam internal network yang selamat.

Encrypted (HTTPS)
Internet ──► Reverse Proxy
Plaintext (HTTP)
Reverse Proxy ──► Backend App
Pengurusan Terpusat

HTTPS Dengan Reverse Proxy

Tanpa Reverse Proxy:

Setiap 10 aplikasi berbeza wajib dipasang sijil SSL masing-masing, dikemas kini manual, dan menguruskan key berasingan.

Dengan Reverse Proxy:

Semua sijil SSL dikelolakan secara terpusat (centralized) pada Reverse Proxy sahaja. Backend apps langsung tidak perlu menguruskan fail sijil SSL!

Automasi Sijil SSL

Certificate Management

ALUR AUTOMATIK ACME (Let's Encrypt / ZeroSSL):
Domain DNS Record
Reverse Proxy ACME Client
TLS Certificate Validated

Automasi pembaharuan sijil (renewal) memastikan website anda tidak mengalami downtime disebabkan sijil SSL expired.

Perbandingan Peranan

Cloudflare vs Local Reverse Proxy

CLOUDFLARE (Edge Proxy)

Menguruskan DNS, perlindungan DDoS, Anycast Routing, dan caching global di seluruh dunia.

LOCAL REVERSE PROXY (Nginx/Caddy)

Menguruskan routing lalulintas dalaman server, port mapping container local, dan internal application rules.

Header Protection

Security Headers

Strict-Transport-Security (HSTS)
Memaksa pelayar web sentiasa mengaplikasikan HTTPS untuk domain tersebut.

Menegah pelayar web daripada "sniffing" MIME-type fail.

Mengawal punca skrip JS dan aset yang boleh dimuat turun.
Perlindungan Trafik

Rate Limiting

Reverse proxy mengehadkan bilangan request yang boleh dihantar oleh 1 IP Address dalam tempoh masa tertentu untuk mengelakkan serangan denial-of-service atau bot spam.

Contoh Had:
limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;
Mengehadkan maksimum 10 request / saat bagi setiap IP.

Troubleshooting Flow

Langkah-Langkah Mengesan Kerosakan:
  1. STEP 1: DNS - Adakah domain resolve ke IP betul? (dig domain.com)

  3. STEP 3: BACKEND PORT - Adakah backend container hidup pada port internalnya?
  4. STEP 4: LOGS - Semak fail error log Reverse Proxy.

Ralat Popular

502 Bad Gateway

Maksud 502 Bad Gateway:

Reverse Proxy berjaya menerima request daripada pelayar, TETAPI gagal berhubung dengan Backend Upstream (Connection Refused / Off).

Punca Utama: App backend belum dipasang (down), nombor port backend dalam proxy config tersilap, atau container terasing dari Docker network.

Ralat Laluan

404 Not Found

Proxy 404:
Reverse Proxy tidak mempunyai rule server_name atau location path bagi URL tersebut.
Application 404:
Proxy berjaya meneruskan request, tetapi routing di dalam perisian backend yang memulangkan 404.
Ralat Halangan

403 Forbidden

Berlaku apabila kebenaran capaian ditolak (Access Control block, IP allowlist block, atau kebenaran kebenaran fail fail statik rosak).

Ralat Enkripsi

Cloudflare Error 525 / SSL Handshake Failed

Tidak wujud ketidakpadanan mod SSL antara Cloudflare (Full/Strict) dengan sijil SSL pada Origin Reverse Proxy anda.

Pemeriksaan Fail Log

Reverse Proxy Logs

Error Log:
Kenapa request gagal dan masalah sambungan ke socket backend.
