02. Kenapa Kita Perlukan Docker?

Bayangkan satu server persendirian yang menjalankan pelbagai perkhidmatan:

❌ Tanpa Container (Tradisional) 

Server
├── Website (Python 3.8)
├── API (Python 3.11) ⚠️ Conflict!
├── Database (PostgreSQL 14)
└── Admin Panel (Node.js 16)
  • Dependency Bercampur: Pustaka (*libraries*) bertindih.
  • Version Conflict: Susah jalankan versi bahasa berbeza.
  • Pemasangan Rumit: Perlu configure OS berulang kali.
  • Sukar Dipindahkan: Susah migrasi ke server baru.

✅ Dengan Docker (Isolated) 

Server (Docker Host)
├── 📦 Container Web (Python 3.8)
├── 📦 Container API (Python 3.11)
├── 📦 Container DB (PostgreSQL 14)
└── 📦 Container Admin (Node 16)

Docker membolehkan setiap aplikasi berjalan dalam persekitaran yang terasing sepenuhnya (isolated) tanpa mengganggu aplikasi lain.

03. Apa Itu Docker?

"Docker ialah platform terbuka untuk membina, menghantar, dan menjalankan application dalam persekitaran terasing yang dipanggil container."

Analogi Kontena Perkapalan

Sama seperti kontena kapal yang boleh memuatkan pelbagai barangan tanpa bercampur dan mudah diangkut oleh mana-mana kapal, Docker membungkus aplikasi bersama semua kekeperluannya.

Aplikasi (Code)
+ Dependencies (Libraries)
+ Configuration (Settings)
↓ 📦 CONTAINER (Siap Dijalankan)

Keuntungan Utamanya:

01

Konsisten: Jika ia berjalan pada laptop anda, ia PASTI berjalan pada server.

02

Pantas: Container boleh di-start dan di-stop dalam beberapa saat sahaja.

03

Clean Server: Tiada sisa fail konfigurasi bertumpuk dalam Host OS.

04. Anatomi Container

Docker Host OS
Container A
App + Libs
Container B
App + Libs
Container C
App + Libs
Shared Host Linux Kernel 🧠

Ciri-Ciri Penting Container:

  • Setia container membawa application, dependencies, dan configurations sendiri.
  • Berkongsi Host Kernel: Berbeza dengan Virtual Machine, container tidak membawa Kernel OS tersendiri.
  • Proses Ringan: Dianggap sebagai satu proses terasing (*isolated process*) biasa pada server host.
  • Ephemere (Sementara): Perubahan fail secara binaan dalam container adalah bersifat sementara melainkan disimpan menggunakan Volume.

05. Docker vs Virtual Machine (VM)

Virtual Machine (Sukar & Berat)

App A | App B | App C
Guest OS (Ubuntu/Windows ~GBs)
Hypervisor (Proxmox/ESXi/VirtualBox)
Host OS
Hardware

VM mensimulasikan perkakasan komputer secara penuh. Memerlukan memori (RAM) dan storan yang besar bagi setiap Guest OS.

Docker Container (Pantas & Ringan)

App A | App B | App C
Docker Engine 🐳
Host OS (Shared Kernel)
Hardware

Container hanya mengandungi kod & kebergantungan sahaja. Tiada overhead Guest OS, saiz lebih kecil (MBs) & boot dalam saat!

💡 Nota Penting: Walaupun container lebih ringan, jangan klaim container sentiasa lebih selamat atau menggantikan VM dalam semua keadaan. Kedua-duanya ada kegunaan tersendiri.

06. Image vs Container (Konsep Utama!)

TEMPLATE / BLUEPRINT

📦 Docker Image

Fail imutabel (*read-only*) yang mengandungi kod, runtime, pustaka, dan tetapan untuk aplikasi.

Analogi: 📖 Resipi Masakan
RUNNING INSTANCE

▶️ Docker Container

Proses yang sedang berjalan (*writeable layer*) yang dijana secara langsung daripada sebuah Image.

Analogi: 🍲 Hidangan yang Dihasilkan
Docker Image ─── docker run ───► Running Container

08. Kitaran Hayat Container (Lifecycle)

Created
➔
Running
➔
Stopped
➔
Removed

Setiap container melalui fasa-fasa ini secara dinamik:

docker run / start:

Memulakan proses utama container.

docker stop:

Memberhentikan proses secara selamat (SIGTERM).

docker restart:

Memulakan semula container (Stop + Start).

docker rm:

Padam container dari memory & storage host.

⚠️ Peringatan Penting: Apabila container dipadam (Removed), semua data baru yang ditulis di dalamnya akan hilang! Ini sebabnya kita perlukan Docker Volume.

09. Command Asas Docker CLI

$ docker --version
Menyemak versi Docker Engine yang terpasang pada host.
$ docker pull nginx
Muat turun Image 'nginx' daripada Docker Hub ke local storage.
$ docker images
Menyenaraikan semua Docker Image yang telah tersimpan.
$ docker ps
Menunjukkan container yang sedang **AKTIF / RUNNING** sahaja.
$ docker ps -a
Menunjukkan **SEMUA** container (termasuk yang Stopped/Exited).

10. Menjalankan Container Pertama

Mari jalankan web server Nginx pertama kita menggunakan command ini:

Terminal Shell 
docker run -d --name my-nginx nginx

Pembedahan Flag Command:

docker run

Cipta container baru dan terus menjalankannya.

-d (detached mode)

Jalankan di latar belakang (*background*), terminal tidak terkunci.

--name my-nginx

Berikan nama unik 'my-nginx' kepada container ini.

nginx

Nama Image yang digunakan (dimuat turun secara automatik jika tiada).

11. Semak Status Container

Gunakan command docker ps untuk melihat output status:

CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS         PORTS     NAMES
a1b2c3d4e5f6   nginx     "/docker-entrypoint.…"   2 minutes ago   Up 2 minutes   80/tcp    my-nginx
STATUS: Up 2 minutes

Menunjukkan container sedang aktif tanpa sebarang sebarang ralat (*crash*).

PORTS: 80/tcp

Nginx dalam container menggunakan port internal 80. (Belum terdedah kepada host!)

docker ps -a

Gunakan `-a` jika anda mahu lihat container yang gagal dibuka (*exited*).

12. Docker Port Mapping (-p)

Untuk membolehkan browser mengakses aplikasi dalam container, kita mesti membuat **Port Mapping**.

$ docker run -d -p 8080:80 --name web nginx
Host Port: 8080 : Container Port: 80
🌐 Web Browser ➔ http://localhost:8080
↓
Server Host Port :8080 ➔ Docker Engine Bridge
↓
Container Nginx Port :80 ➔ Menerima HTTP Request! ✅

13. Port Mapping ≠ Router Port Forwarding

📡 Router Port Forwarding

Menghubungkan trafik awam luar (*Public Internet*) menerusi Router ke server tempatan anda.

Internet
  ↓ (Public IP)
Router House
  ↓ (Port Forwarding 80->8080)
Server Laptop (Private IP)

🐳 Docker Port Mapping

Menghubungkan port pada Server Host tempatan ke port dalaman Container terasing.

Server Host Port :8080
  ↓ (Docker Port Mapping)
Docker Internal Network
  ↓
Container Nginx Port :80
💡 Kesimpulan: Docker Port Mapping beroperasi di dalam mesin host sahaja. Ia tidak membuka port ke internet secara automatik tanpa persediaan Network Router atau Tunnel.

16. Storan Kekal: Docker Volume

❌ Masalah Data Sementara

Secara lalai, sebarang fail baru yang ditulis di dalam container disimpan dalam lapisan sementara (*ephemeral layer*).

Container Removed ➔ ALL DATA DELETED! 💥

✅ Penyelesaian: Docker Volume

Volume mengasingkan direktori simpanan fail terus ke dalam sistem fail Host Server.

Container Removed ➔ Data Volume Remains Safe! 🛡️

17. Konsep & Visualisasi Volume

📦 Container Database (PostgreSQL)
Path: /var/lib/postgresql/data
↓ Volume Mount (-v)
💾 Docker Volume (Host Storage)
Path: /var/lib/docker/volumes/db_data

Walaupun anda memadam atau mengemas kini (*upgrade*) container database, data perniagaan anda dalam Volume kekal utuh!

18. Rangkaian Docker (Docker Network)

Container dalam host yang sama boleh berkomunikasi antara satu sama lain melalui **User-Defined Bridge Network**.

🌐 Docker Custom Network (my-network)
Web Container
IP Internal Docker
API Container
IP Internal Docker
Database Container
IP Internal Docker

Docker menyertakan pelayan **Internal DNS**. Anda tidak perlu menghafal alamat IP container yang sentiasa berubah!

19. Komunikasi Antara Container

Gunakan Service / Container Name sebagai Hostname!

❌ SALAH (Jangan Gunakan localhost):
DATABASE_HOST=localhost

`localhost` di dalam container merujuk kepada container itu sendiri, bukan host atau container lain.

✅ BETUL (Gunakan Service Name):
DATABASE_HOST=database
API_URL=http://api:5000

Docker DNS akan me-resolve nama container ke IP internal secara automatik.

20. Misteri 'localhost' Dalam Container

Container A (Web)
localhost = Container A 🏠
Container B (API)
localhost = Container B 🏠
Container A `localhost` ≠ Container B `localhost` ≠ Host Server `localhost`

Setiap container mempunyai rangkaian loopback (`127.0.0.1` / `localhost`) tersendiri yang terasing. Oleh itu, panggilah perkhidmatan lain dengan Nama Container / Service dalam network yang sama.

21. Kenapa Kita Perlukan Docker Compose?

❌ Tanpa Docker Compose

Anda perlu menaip banyak command CLI panjang satu per satu:

docker network create my-net
docker run -d --net my-net --name db postgres
docker run -d --net my-net --name api -p 5000:5000 my-api
docker run -d --net my-net --name web -p 8080:80 my-web

✅ Dengan Docker Compose

Tentukan semua aplikasi dalam 1 fail deklaratif (`compose.yaml`):

$ docker compose up -d

Satu command sahaja untuk melancarkan keseluruhan infrastructure multi-container!

22. Struktur Fail compose.yaml

compose.yaml 
services:
  web:
    image: nginx
    ports:
      - "8080:80"
services:

Senarai bekas perkhidmatan yang ingin dijalankan.

image:

Docker Image yang akan di-pull secara automatik.

ports:

Pemetaan port host ke port container (`host:container`).

23. Multiple Services Dalam Compose 

services:
  web:
    image: nginx
    ports:
      - "8080:80"

  api:
    image: python:3.11
    ports:
      - "5000:5000"

  db:
    image: postgres:15
🚀 Kelebihan Penting:

Docker Compose secara automatik akan mencipta **1 Rangkaian Khas (Network)** untuk ketiga-tiga perkhidmatan ini saling berhubung tanpa perlu konfigurasi IP manual.

24. Aliran Kerja (Flow) Docker Compose

📄 compose.yaml
➔
docker compose up -d
➔
All Services Active!
$ docker compose up -d

Mencipta network, volume, dan melancarkan semua container mengikut hirarki.

$ docker compose down

Memberhentikan dan memadam container serta network secara bersih (clean up).

31. Asas Keselamatan (Docker Security)

⚠️ AMARAN: Pengasingan Container bukanlah jaminan keselamatan mutlak (*absolute security guarantee*).
✓ HTTPS / SSL

Enkripsi semua trafik luar.

✓ Firewall (UFW)

Tutup port yang tidak perlu.

✓ Kemaskini Image

Pull imej tampalan (*security patch*).

✓ Non-root User

Jalankan app tanpa kebenaran root.

32. Keselamatan Pangkalan Data (Database)

❌ BAHAYA (Expose DB Port)

db:
  image: postgres
  ports:
    - "5432:5432" # ⚠️ Terdedah ke awam!

Penggodam di luar boleh cuba me-bruteforce kata laluan database anda.

✅ SELAMAT (Internal Network Only)

db:
  image: postgres
  # Tiada bahagian 'ports:'!

Database hanya boleh dicapai oleh API Container di dalam Docker Network internal sahaja.

33. Pengurusan Secret (Environment Variables)

JANGAN SEKALI-KALI meletakkan kata laluan atau API Key secara hardcode dalam fail kod!

// Gunakan fail .env atau placeholder:
DATABASE_URL=<DATABASE_URL>
SECRET_KEY=<API_KEY>

34. Semakan Log (Troubleshooting)

Apabila aplikasi terhenti atau mengalami ralat, log ialah kawan terbaik anda:

$ docker logs -f <CONTAINER_NAME>
  • Guna flag -f untuk melihat log secara masa nyata (*real-time live stream*).
  • Membantu mengesan masalah ralat sambungan DB, Port conflict, atau sintaks kod.

35. Pengurusan Sumber (Resource Limits)

"Container bukan kotak ajaib (*magic box*). Ia masih berkongsi CPU, RAM, dan Disk Host."
$ docker stats

Pantau penggunaan sumber CPU & Memory secara langsung untuk memastikan server tidak kehabisan RAM (*Out Of Memory Crash*).

37. Development vs Production Deployment

💻 Development (Local Laptop)

  • Fokus pada kepantasan pembangunan.
  • Expose port ke `localhost`.
  • Gunakan Bind Mounts untuk live-reload kod.

🚀 Production (VPS / Server / Pi)

  • Fokus keselamatan, kestabilan & backup.
  • Gunakan Reverse Proxy / Cloudflare Tunnel.
  • Automated Restart Policy (`restart: always`).

39. Kesilapan Lazim Pemula (Common Mistakes)

❌ Menganggap Container sama persis seperti Virtual Machine.
❌ Menggunakan `localhost` untuk berhubung ke container lain.
❌ Lupa menggunakan Volume untuk menyimpan data kekal.
❌ Mendedahkan (expose) port database terus ke Internet.
❌ Menulis kata laluan rahsia secara terus dalam kod.
❌ Tidak membuat salinan sandaran (backup) berkala.
