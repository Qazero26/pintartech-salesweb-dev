TRANSPORT LAYER

Port — Pintu Masuk Perkhidmatan

Analogi Bangunan & Pintu

🏢 IP Address: Alamat Bangunan Fizikal
🚪 Port: Nombor Pintu Bilik / Pejabat di dalam bangunan tersebut.

Port Standard Biasa:

80: HTTP Web
443: HTTPS Secure
22: SSH Remote
8080: Dev Web Server
Satu machine (IP) boleh menjalankan banyak aplikasi serentak, dan Port membezakan aplikasi mana yang patut terima data tersebut!
TRANSPORT PROTOCOL

TCP — Membina Connection

TCP 3-Way Handshake
Client ➔ Server SYN "Boleh kita bercakap?"
Server ➔ Client SYN-ACK "Boleh! Saya sedia."
Client ➔ Server ACK "OK, Connection Diwujudkan!"
🤝 Sambungan TCP memastikan data tidak hilang dan disusun mengikut urutan yang betul.
COMPARISON

TCP vs UDP

TCP (Transmission Control Protocol)

  • Connection-oriented (perlu handshake)
  • Reliable delivery (jaminan data sampai)
  • Ordered data (susunan terjamin)
  • Digunakan oleh: HTTP, HTTPS, SSH, Email

UDP (User Datagram Protocol)

  • Connectionless (tiada handshake)
  • Lower overhead & lebih pantas
  • Tidak menjamin data sampai 100%
  • Digunakan oleh: DNS, Video Streaming, Gaming
💡 Ingat: UDP bukan bermaksud "tidak berguna" atau "tidak selamat". Ia direka untuk aplikasi yang mengutamakan kelajuan pantas melebihi kepastian.
SECURITY LAYER

HTTPS — Enkripsi Rangkaian

http://example.com

HTTP biasa (Tidak Selamat)

Data dihantar secara plain-text. Sesiapa di tengah (hacker/WiFi awam) boleh membaca password anda.

🔒 https://example.com

HTTPS (Dengan TLS Enkripsi)

Data di-encrypt sebelum dihantar. Hanya server destinasi sahaja boleh dekod semula data tersebut.

HTTPS menyediakan 3 tiang utama: Encryption (Kerahsiaan), Authentication (Pengesahan Identiti), dan Integrity (Tiada olahan data).
SECURITY PROCESS

TLS Handshake (Konsep Ringkas)

1. Client Hello "Saya nak connect guna TLS 1.3"
2. Server Hello + Certificate "Ini Certificate sah saya"
3. Key Negotiation Hasilkan Session Key bersama
4. Encrypted Traffic Begins 🔒 Saluran selamat diwujudkan!
(Nota: Perlaksanaan TLS sebenar melibatkan cryptography matematik seperti RSA/ECC & Ephemeral Diffie-Hellman).
AUTHENTICATION

TLS Certificate

📜

Digital SSL/TLS Certificate

Issued to: example.com

Certificate membantu browser mengesahkan bahawa anda betul-betul sedang berhubung dengan server yang sahih, bukannya penyamar (Man-in-the-Middle attack).

🛑 Pembetulan Istilah Penting: Jangan kata "Certificate yang meng-encrypt website".
Yang Tepat: TLS menggunakan certificate sebagai sebahagian daripada proses authentication dan penetapan kunci enkripsi (key establishment).

SERVER ARCHITECTURE

Web Server vs Application

Web Server (cth: Nginx / Apache)

  • Menerima sambungan HTTP awal
  • Mengendalikan fail statik (HTML, CSS, Image)
  • Bertindak sebagai Reverse Proxy & Security Guard

Application (cth: Python / Node.js)

  • Menjalankan logic perniagaan (Business Logic)
  • Bercakap dengan Database
  • Memproses authentication, bayaran & API
Browser ➔ Nginx (Web Server) ➔ Python App (Backend Application)

COMPARISON MATRIX

Port Forwarding vs Tunnel

PORT FORWARDING

  • Laluan: Inbound (Masuk) melalui Router
  • Perlu kawalan penuh akses Router rumah/ofis
  • Mengedahkan Public IP rumah anda secara langsung
  • Sukar jika ISP guna Carrier-Grade NAT (CGNAT)

TUNNEL (ngrok / Cloudflare)

  • Laluan: Outbound (Keluar) ke Cloud
  • Tiada sebarang usikan pada Router
  • Menyembunyikan Public IP fizikal anda
  • Berfungsi walaupun di sebalik CGNAT / WiFi Kedai

INSIDE THE SERVER

Apa Yang Berlaku Pada Server?

Request: GET /index.html ➔ Web Server / App ➔ File System ➔ Response: 200 OK

1. CPU server menerima interrupt sambungan kad rangkaian.

2. Socket OS menghantar byte data ke port yang dipasang (listen).

3. Application membaca fail dari hard disk / SSD.

4. Mesej jawapan dibungkus semula dalam format HTTP Response.
