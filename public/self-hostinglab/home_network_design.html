Perbandingan Boundary

Internet vs Home Network

INTERNET (WAN)

  • Public network global
  • Untrusted by default (penuh ancaman)
  • Diuruskan oleh ISP & global routing

HOME NETWORK (LAN)

  • Private Local Area Network
  • Dikawal sepenuhnya oleh korang
  • Tempat simpanan data & local services
🌐 Internet (Public) ──── Boundary Router ──── 🏠 Home Private LAN
Infrastruktur Akses

ISP — Internet Service Provider

ISP menyediakan gateway fizikal dan logikal untuk menyambungkan rumah anda ke laluan Internet global.

WHAT

Syarikat telekomunikasi yang membekalkan bandwidth & Public IP Address.

WHY

Tanpa ISP, korang tak boleh access server luar atau terima inbound connection.

REAL WORLD

Contoh medium: Fiber Optics (FTTH), Cable, 5G Home Wireless, DSL.

Prinsip Penting: Jangan bergantung pada teknologi akses tertentu. Sama ada korang guna Fiber atau 5G, konsep routing dan segmentation dalam homelab tetap SAMA!
Hardware Medium Conversion

ONT / Modem

Fiber Optics → ONT

Optical Network Terminal (ONT) menukar isyarat cahaya (fiber) kepada isyarat elektrik Ethernet (RJ45).

Cable / DSL → Modem

Modem (Modulator-Demodulator) menukar isyarat analog kualiti frekuensi ke isyarat digital paket data.

Fungsi Utama:

Menukar/menyambung access medium luaran kepada kelengkapan networking korang. Tidak semua rumah menggunakan device yang sama (ada AIO ONT+Router combo, ada Bridge Mode).

Wireless Security

Wi-Fi & Standard Keselamatan

Wi-Fi adalah medium tanpa wayar yang mendedahkan data korang ke udara. Keselamatan Wi-Fi amat kritikal.

Security Protocols
  • WEP / WPA (Deprecated): Sangat berasid & mudah digodam beberapa minit.
  • WPA2-PSK (AES): Standard minimum masa kini.
  • WPA3-SAE: Standard moden terbaik dengan PMF (Protected Management Frames).
Best Practices Homelab Wi-Fi
  • Gunakan Wi-Fi password yang panjang & kompleks.
  • Update firmware AP secara berkala.
  • Nyahaktifkan WPS (Wi-Fi Protected Setup).
  • Asingkan Guest / IoT ke Wi-Fi SSID berbeza.
Boundary Networks

LAN (Local) & WAN (Wide) Area Networks

LAN (Local Area Network)

Rangkaian dalaman rumah. Semua device berhubung pada kelajuan gigabit/multi-gigabit tempatan.

IP Contoh: 192.168.1.0/24
Latency: <1ms

WAN (Wide Area Network)

Rangkaian global luar. Menghubungkan router korang ke pelayan ISP dan seluruh dunia.

Public IP: 203.0.113.10
Latency: 5ms - 100ms+

IP Addressing

Home Network IP Plan Asas

Pengurusan IP Address yang tersusun membolehkan korang mengenalpasti peranti homelab dengan pantas.

SUBNET RANGKAIAN: 192.168.1.0/24
Router / Gateway: 192.168.1.1
Workstation PC: 192.168.1.10
NAS Storage: 192.168.1.20
Raspberry Pi Server: 192.168.1.50
Sebab Penting: Tanpa skema IP yang dirancang, pelayan korang mungkin bertukar-tukar IP, menyebabkan connection ke Docker, SSH, dan Reverse Proxy terputus!
Dynamic Addressing

DHCP (Dynamic Host Configuration Protocol)

DHCP mengagihkan IP Address dan tetapan rangkaian secara automatik kepada setiap device yang connect.

Parameter Disampaikan Oleh DHCP:
  • • IP Address (cth: 192.168.1.105)
  • • Subnet Mask (cth: 255.255.255.0)
  • • Default Gateway (cth: 192.168.1.1)
  • • DNS Servers (cth: 1.1.1.1, 192.168.1.1)
DORA Process:
1. Discover (Device ➔ All)
2. Offer (DHCP ➔ Device)
3. Request (Device ➔ DHCP)
4. Acknowledge (DHCP ➔ Device)
Addressing Strategies

Static IP vs DHCP Reservation

Static IP (Manual)

IP ditetapkan secara manual dalam OS device (contoh: dalam `/etc/netplan` Linux).

  • ✓ Tidak bergantung pada router/DHCP server
  • ✗ Kena ingat dan elak IP konflik secara manual

DHCP Reservation (MAC Binding)

Router sentiasa memberikan IP yang sama kepada MAC Address peranti tersebut.

  • ✓ Mudah dikelola berpusat di router
  • ✓ Rekabentuk IP centralized yang sangat kemas
Rekomendasi Homelab: Untuk server/NAS, DHCP Reservation lebih disukai kerana mengelakkan masalah perselisihan subnet jika router ditukar kelak.
Subnet Segmentation

IP Address Allocation Plan

Contoh pembahagian IP julat julat spesifik dalam subnet /24:

192.168.1.1 Network Gateway / Main Router
192.168.1.10 – 192.168.1.49 Static Clients (Workstations, Printers)
192.168.1.50 – 192.168.1.79 Homelab Servers (Raspberry Pi, Proxmox, NAS)
192.168.1.80 – 192.168.1.99 Network Equipment (Switches, Access Points)
192.168.1.100 – 192.168.1.199 Dynamic DHCP Pool (Phones, Guest Laptops)
Name Resolution

DNS Dalam Home Network

DNS menukarkan IP Address yang sukar diingati kepada hostname yang mesra pengguna.

router.home
➔ 192.168.1.1
nas.home
➔ 192.168.1.20
pihole.home
➔ 192.168.1.50
Kelebihan Internal DNS: Korang tidak perlu menghafal nombor IP server. Anda boleh install Pi-hole atau AdGuard Home untuk DNS tempatan bertindak sebagai ad-blocker seluruh rumah!
IPv4 Sharing

NAT (Network Address Translation)

NAT membolehkan berpuluh peranti dalam private LAN berkongsi **SATU Public IPv4 Address** untuk berkomunikasi ke Internet.

Laptop (192.168.1.10:54321) [ Router NAT Engine ] Public IP (203.0.113.10:12345) Internet Web Server
Sebab Kewujudan: Alamat IPv4 awam terhad secara global. NAT menyelesaikan kekurangan ini dan bertindak sebagai pelindung asas daripada serangan terus luar.
Network Defense

Firewall — Benteng Rangkaian

Firewall menapis paket data berdasarkan set peraturan keselamatan (Allow / Deny).

🌐 Public Internet
⬇ [ FIREWALL (Drop Inbound Requests) ]
🏠 Private Home LAN
AMARAN HOMELAB: Jangan bergantung *hanya* pada router firewall! Jika satu peranti LAN dijangkiti malware, ia boleh menyerang peranti lain dalam subnet yang sama jika tiada segmentation.

Isolation Architecture

Network Segmentation — Pengasingan Rangkaian

Konsep utama: **Jangan letakkan semua peranti dalam satu broadcast domain yang sama** jika tahap risiko peranti berbeza!

Flat Network (Tanpa Segmentation)

IoT Camera terjangkit ➔ Terus scan & hack NAS Storage & Raspberry Pi Server korang!

Segmented Network (Dengan VLAN)

IoT Camera terjangkit ➔ Dihalang oleh Firewall daripada akses Server VLAN & Client VLAN!

Logical Mapping

Memadankan Subnet & VLAN

Secara amalan terbaik, setiap ID VLAN dipadankan dengan satu Subnet IP yang sepadan untuk memudahkan kenalpasti.

VLAN 10 (Clients) 192.168.10.0/24
VLAN 20 (Servers) 192.168.20.0/24
VLAN 30 (IoT) 192.168.30.0/24
VLAN 40 (Guests) 192.168.40.0/24
VLAN 99 (Management) 192.168.99.0/24
Nota Konseptual: VLAN ialah teknologi Layer 2 (Data Link), manakala Subnet ialah Layer 3 (Network). Mereka sering dipasangkan bersama tetapi adalah perkara yang berbeza!
VLAN 10

Client VLAN (VLAN 10)

Peranti Terlibat:

Workstation PC, Laptop peribadi, Smartphone harian, Tablet.

Policy Keselamatan:

Boleh akses Internet penuh. Boleh akses web services di Server VLAN (Port 80/443).

VLAN 20

Server VLAN (VLAN 20)

Peranti Terlibat:

Raspberry Pi, Dedicated Linux Server, Proxmox VE Host, NAS Storage, Monitoring Node.

Policy Keselamatan:

Hanya benarkan trafik web terhad inbound. Hapus sebarang akses direct dari IoT atau Guest VLAN!

VLAN 30

IoT VLAN (VLAN 30)

Peranti Terlibat:

IP Cameras, Smart Plugs, Smart TV, Smart Speakers, Air Conditioner Controllers.

Policy Strict:

Dilarang sama sekali daripada memulakan sambungan (outbound connection) ke VLAN Clients atau Server!

VLAN 40

Guest VLAN (VLAN 40)

Khusus untuk telefon bimbit atau laptop tetamu yang melawat rumah anda.

POLICY: Guest ➔ Internet ONLY ✅ | Guest ➔ Internal LAN ❌ (BLOCKED)
VLAN 99

Management VLAN (VLAN 99)

Network paling sensitif yang menyimpan antaramuka kawalan hardware infrastructure.

• Switch Admin Interface
• Router Admin Portal
• Access Point Controllers
• NAS Out-of-band Admin Portal (iDRAC / IPMI)

Akses hanya dibenarkan dari PC Admin khas melalui VPN atau wired port terasing.

Firewall Rules

Inter-VLAN Firewall Rules

Segmentation tidak bermakna jika tiada polisi firewall yang menghalang atau membenarkan laluan.

Client VLAN ➔ Server VLAN (Port 443 HTTPS) ALLOW ✅
Client VLAN ➔ Server VLAN (Port 22 SSH) DENY ❌ (Kecuali IP Admin)
IoT VLAN ➔ Server VLAN (All Ports) DENY ❌
Guest VLAN ➔ Internal Networks DENY ❌

Legacy Inbound

Port Forwarding Tradisional & Risikonya

Internet ➔ Public IP:80 ➔ Main Router ➔ Forward ➔ Server LAN:80
Kelemahan & Risiko:
  • Mendedahkan Public IP rumah kepada pengimbas botnet global (Shodan/Censys).
  • Pendedahan terus jika web server ada Zero-Day Vulnerability.
  • Memerlukan Public IP statik atau Dynamic DNS (DDNS).

Troubleshooting

Kegagalan DNS (DNS Failure Scenario)

Apabila DNS Server down, Internet masih hidup tetapi hostname resolution gagal!

Simptom: Website tidak boleh dibuka melalui domain, tetapi `ping 1.1.1.1` BERJAYA!
Solusi: Setkan secondary upstream DNS fallback atau mulakan semula Pi-hole service.
Troubleshooting

Kegagalan DHCP Server

Apabila DHCP Server down:

• Peranti sedia ada terus berfungsi sehingga lease time tamat.
• Peranti baharu mendapat IP Self-Assigned/APIPA (`169.254.X.X`).
