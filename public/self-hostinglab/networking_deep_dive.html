ASAS ARCHITECTURE

Kenapa Networking Penting?

Application anda tidak pernah bercakap secara terus dengan Internet. Data perlu melalui susunan 5 lapisan (Network Stack):

LAYER 5 Application HTTP, SSH, DNS
LAYER 4 Transport TCP, UDP, Ports
LAYER 3 Network IP, Routing, Subnet
LAYER 2 Link MAC Address, ARP
LAYER 1 Physical Cable, Wi-Fi, Signal
🔍 Poin Kunci: Peranan utama Network Layer (IP) ialah menentukan ke mana data perlu pergi dan jalan mana yang perlu dilalui.

IDENTITI RANGKAIAN

Apa itu IP Address?

IP Address (Internet Protocol Address) ialah alamat logik unik yang diberikan kepada setiap peranti yang disambungkan ke rangkaian.

Contoh Format IPv4 (Dotted-Decimal):
192. 168. 1. 50
Alamat ini membolehkan penghala (router) dan pelayan (server) tahu siapa penghantar dan ke mana penerima sesuatu data.
STRUCTURE

Anatomi IPv4 (32-Bit Address)

Decimal Representation

192 . 168 . 1 . 50

4 Octet (Nombor 0 hingga 255 bagi setiap bahagian).

Binary Representation (32 Bits)

11000000 . 10101000 . 00000001 . 00110010

8 bits + 8 bits + 8 bits + 8 bits = 32 bits jumlahnya.

💡 Komputer dan router memproses alamat ini sebagai nombor biner 0 dan 1, manakala manusia membacanya dalam bentuk nombor perpuluhan (decimal).
RANGKAIAN TEMPATAN

Private IPv4 Ranges

RFC 1918 menetapkan 3 julat alamat khas yang hanya boleh digunakan dalam LAN tempatan dan tidak di-route di Internet awam:

Class A
10.0.0.0/8
10.0.0.0 – 10.255.255.255 (Biasa di Enterprise / AWS VPC)
Class B
172.16.0.0/12
172.16.0.0 – 172.31.255.255 (Biasa di Docker Containers)
Class C
192.168.0.0/16
192.168.0.0 – 192.168.255.255 (Biasa di Router Rumah / Offis)
Contoh kegunaan: Laptop (192.168.1.10), Raspberry Pi (192.168.1.50), Router (192.168.1.1).

COMPARISON

Private vs Public IP

PRIVATE IP

  • Digunakan dalam local network (LAN) sahaja.
  • Percuma & boleh dipakai berulang di mana-mana rumah.
  • Tidak boleh di-route secara terus di Internet.
  • Contoh: 192.168.1.10

PUBLIC IP

  • Unik secara global di seluruh dunia.
  • Diberikan oleh ISP / Cloud Provider.
  • Boleh dicapai (routable) di Internet awam.
  • Contoh Dokumentasi: 203.0.113.10
(Nota: IPv4 203.0.113.0/24 diguna sebagai blok alamat dokumentasi rasmi RFC 5737).

Subnet menentukan: "Network mana peranti ini berada?"

Network Address: 192.168.1.0

PREFIX LENGTH

CIDR — /24, /16, /8?

CIDR (Classless Inter-Domain Routing) menggunakan tatatanda /24 untuk menunjukkan berapa bit dikhaskan untuk Network Portion.

192.168.1.0 /24 Total 32 Bits
8 Bits 11111111
8 Bits 11111111
8 Bits 11111111
8 Bits (Host) 00000000
← Network Portion (24 Bits) → ← Host (8 Bits) →
MASKING

Subnet Mask

Subnet Mask ialah cara tradisional menulis prefix length CIDR dalam format 4 octet:

/24
255.255.255.0
254 Usable Hosts
/16
255.255.0.0
65,534 Usable Hosts
/8
255.0.0.0
16,777,214 Hosts
💡 CIDR (contoh: /24) ialah singkatan moden untuk memudahkan penulisan Subnet Mask.
ADDRESS ROLES

Komponen Alamat Subnet

Contoh IP: 192.168.1.50/24
NETWORK ADDRESS 192.168.1.0

Identiti bagi seluruh subnet (tidak boleh diguna oleh host).

HOST ADDRESSES 192.168.1.1 – .254

Alamat yang boleh diberikan kepada PC, Pi, Server, Router.

BROADCAST ADDRESS 192.168.1.255

Digunakan untuk menghantar mesej ke semua device dalam subnet.

ROUTING ALGORITHM

Longest Prefix Match

Apabila router menerima packet, ia memilih route yang paling spesifik (prefix length terbesar):

Destinasi Packet: 10.1.2.50
10.0.0.0/8 Match (8 bits)
10.1.0.0/16 Match (16 bits)
10.1.2.0/24 ✅ CHOSEN (Paling Spesifik: 24 bits)
AUTO CONFIGURATION

DHCP (Proses DORA)

DHCP (Dynamic Host Configuration Protocol) memberikan konfigurasi IP secara automatik kepada peranti melalui 4 langkah (DORA):

1. DISCOVER Client broadcast: "Ada DHCP Server tak?"
2. OFFER Server tawar: "Guna IP 192.168.1.50 ini."
3. REQUEST Client minta: "Saya nak IP 192.168.1.50 itu."
4. ACK Server sahkan: "OK! IP disahkan milik anda."

LAYER 2 IDENTITY

MAC Address (Link-Layer)

IP Address (Layer 3)

192.168.1.50

Alamat logik yang boleh bertukar mengikut lokasi network.

MAC Address (Layer 2)

AA:BB:CC:DD:EE:FF

Alamat fizikal kekal yang tertanam pada kad rangkaian (NIC hardware).

Dalam satu LAN tempatan, peranti berkomunikasi secara terus menggunakan MAC Address, bukan IP!
LAYER 2 TO LAYER 3

ARP (Address Resolution Protocol)

Bagaimana Device Cari MAC Address Berdasarkan IP?
Laptop: "Siapa ada IP 192.168.1.50? Sila beri MAC anda!" (Broadcast)
Raspberry Pi: "Saya! IP 192.168.1.50 ada pada MAC AA:BB:CC:DD:EE:FF."
IPv4 memerlukan ARP untuk menterjemahkan IP destinasi kepada MAC Address tempatan.
NEIGHBOR TABLE

ARP Cache (`ip neigh`)

Terminal Output: Neighbor Table
$ ip neigh

192.168.1.50 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE

TRANSPORT PROTOCOL

TCP (Transmission Control Protocol)

Ciri-Ciri Utama TCP:

  • Connection-oriented: Mesti bina sambungan sebelum hantar data.
  • Reliability: Packet yang hilang akan di-retransmit semula.
  • Ordering: Data disusun semula mengikut urutan asal.
  • Flow Control: Menyesuaikan kelajuan penghantaran mengikut penerima.
Sesuai untuk perkhidmatan yang perlukan ketepatan 100% seperti HTTPS, SSH, Web Server, E-mel.
ESTABLISHING CONNECTION

TCP 3-Way Handshake Interactive

Client Status: Disconnected Server
Client ➔ Server SYN (Synchronize) "Bolehkah kita connect?"
Server ➔ Client SYN-ACK "Boleh! Saya setuju."
Client ➔ Server ACK (Acknowledge) "OK! Sambungan terbina."
TRANSPORT PROTOCOL

UDP (User Datagram Protocol)

Ciri-Ciri Utama UDP:

  • Connectionless: Tiada handshake awal, data terus dihantar.
  • Low Overhead: Header sangat kecil dan pantas.
  • No Delivery Guarantee: Jika paket hilang, ia tidak di-retransmit.
  • Digunakan oleh: DNS, DHCP, Video Streaming, Gaming, HTTP/3 (QUIC).
⚠️ Ingat: UDP bukan "tidak selamat" atau "buruk". Ia direka khusus untuk aplikasi yang mementingkan kelajuan masa nyata (real-time speed).
COMPARISON MATRIX

TCP vs UDP

TCP

  • Connection-oriented (Handshake)
  • Reliable (Jaminan data sampai)
  • Ordered (Susunan terjamin)
  • Higher overhead

UDP

  • Connectionless (Tiada handshake)
  • No Delivery Guarantee
  • No Ordering Guarantee
  • Lower Protocol Overhead
💡 Pilih protocol berdasarkan keperluan aplikasi anda!

COMMUNICATION ENDPOINT

Apa itu Socket?

Formula Socket Kombinasi:
[Protocol] + [IP Address] + [Port Number]
Contoh: TCP   192.168.1.50 : 443
Socket ialah titik hujung (endpoint) sebenar dalam sistem pengendalian (OS) yang digunakan oleh aplikasi untuk menghantar dan menerima aliran data.

TRAFFIC FILTERING

Firewall — Tapis Lalu Lintas

Firewall menapis lalu lintas rangkaian berdasarkan kriteria peraturan yang ditetapkan:

Source IP Dari mana packet datang
Destination IP Ke mana packet hendak pergi
Protocol TCP, UDP, ICMP
Port Number Port 22, 80, 443, 8080
Interface eth0, wlan0, tun0
State NEW, ESTABLISHED
STATEFUL INSPECTION

Stateful Firewall

Stateful Firewall mengingati status sambungan keluar (Outbound Connection).
1. Client ➔ Outbound to Web Allowed & Tracked
2. Server ➔ Inbound Response ✅ Auto Allowed (ESTABLISHED)
Anda tidak perlu buka port inbound untuk menerima balasan jawapan daripada web yang anda layari!
SEGMENTATION

VLAN (Virtual LAN)

VLAN: Memisahkan satu physical switch kepada beberapa rangkaian logik bebas di Layer 2.

VLAN 10 Management

SECURITY DESIGN

Network Segmentation

Tujuan Segmentasi Rangkaian:

  • Pengasingan (Isolation): Jika peranti IoT dijangkiti malware, ia tidak boleh menyerang Server tempatan anda.
  • Reduce Attack Surface: Mengecilkan skop capaian pihak luar.
  • Easy Management: Memudahkan kawalan polisi firewall mengikut zon.
DISTINCTION

VLAN vs Subnet

VLAN (Layer 2)

Segmen pengasingan logik pada peringkat Ethernet switch / hardware.

SUBNET (Layer 3)

Segmen pengelompokan alamat IP dalam protokol IP.

Biasanya 1 VLAN dipetakan kepada 1 Subnet.
Contoh: VLAN 20 ↔ Subnet 192.168.20.0/24
CROSS-VLAN COMMUNICATION

Inter-VLAN Routing & Firewall Policy

✓ User ➔ Server : Port 443 (HTTPS) ALLOWED
✗ User ➔ Server : Port 22 (SSH) BLOCKED

NEXT-GEN PROTOCOL

Asas IPv6 (128-Bit Address)

IPv6 dicipta untuk mengatasi kekurangan alamat IPv4 dengan saiz 128-bit address space.

Contoh Format Hexadecimal IPv6:

(Nota: IPv6 2001:db8::/32 digunakan khas untuk tujuan dokumentasi).
COMPARISON

IPv4 vs IPv6

IPv4

  • 32-bit (4.3 Bilion alamat)
  • Dotted decimal (192.168.1.50)
  • Memerlukan NAT untuk penjimatan IP

IPv6

  • 128-bit (Alamat tanpa had)
  • Hexadecimal (2001:db8::1)
  • Setiap peranti mendapat Public IP terus (Tiada NAT)

REAL SCENARIO 1

X Boleh Access Raspberry Pi (Port 8080)

Masalah: Laptop (192.168.1.10) cuba buka http://192.168.1.50:8080 tetapi GAGAL.
Langkah Troubleshooting Berperingkat:
1. ping 192.168.1.50 ➔ Adakah IP boleh dicapai?
2. ss -tulpn | grep 8080 ➔ Adakah Python/App betul listening di port 8080?
3. curl localhost:8080 (dari Pi) ➔ Adakah app berjalan secara tempatan?
4. sudo ufw status ➔ Adakah Firewall menyekat port 8080?
REAL SCENARIO 2

Ping Berjaya Tetapi Web Gagal

ping 192.168.1.50 ➔ OK! (Layer 3 Sihat)
curl http://192.168.1.50:8080 ➔ Connection Refused!

Sebab utama:

  • Aplikasi down / crashed.
  • Aplikasi tersalah bind IP (cth: bind ke 127.0.0.1 bukannya 0.0.0.0).
  • Firewall menyekat port 8080.
💡 Prinsip Kunci: Network reachability (ping) TIDAK SAMA dengan Application availability!
REAL SCENARIO 3

IP Berubah Selepas Reboot

Sebelum Reboot: 192.168.1.50
Selepas Reboot: 192.168.1.87 (Sebab lease DHCP tamat)
Solusi 1: DHCP Reservation Tetapkan pada Router (Disyorkan).
Solusi 2: Static IP Tetapkan terus pada OS Raspberry Pi.
REAL SCENARIO 4

DNS Resolve Berjaya Tetapi Website Gagal

dig app.example.com ➔ 203.0.113.10 (DNS OK!)
Website ➔ 502 Bad Gateway / Connection Timeout
💡 Pengajaran: Kejayaan DNS resolution hanya membuktikan buku telefon (DNS) berfungsi. Ia tidak menjamin server atau tunnel di belakangnya aktif!
