Cabaran Menggunakan Direct Public IP

1. Public IP Selalu Berubah (Dynamic IP)

ISP biasa (seperti TM Unifi) tukar IP rumah anda setiap kali router di-restart.

2. Server Terdedah Terus (Direct Exposure)

Bot dan penggodam di internet boleh *scan* Public IP anda 24 jam sehari.

3. Sambungan HTTP Tidak Encrypted

Tiada ikon mangga keselamatan (HTTPS). Browser tunjuk "Not Secure".

⚠️ Direct Exposure Danger

Masalah Keselamatan

Kenapa HTTP Tidak Cukup?

http://app.domainbos.com:8080

Apabila laman web menggunakan HTTP (HyperText Transfer Protocol) biasa, semua data dihantar dalam bentuk plain text (teks biasa tanpa encrypt).

⚠️ Password & data boleh diintip di tengah jalan (Eavesdropping).
⚠️ Browser moden akan tunjuk amaran merah "Not Secure".

Paparan Pelayar Web (Browser Warning)

Not Secure — http://app.domainbos.com
Solusi Keselamatan

Apa itu HTTPS?

HTTP + Encryption + Certificate

HTTPS (HTTP Secure) meng-encrypt semua lalu lintas data antara browser pengguna dan web server supaya tidak boleh dibaca oleh pihak ketiga.

https://app.domainbos.com

HTTPS Encrypted PORT 443

Port standard dunia untuk trafik web selamat (SSL/TLS Encrypted).

Identiti Web

Apa itu SSL / TLS Certificate?

Cad Pengenalan Rasmi Website

SSL Certificate ialah fail digital khas yang membuktikan identiti domain anda dan menyediakan "kunci encryption" untuk keselamatan.

Percuma Dengan Let's Encrypt

Zaman dulu SSL mahal, tetapi kini badan seperti Let's Encrypt menyediakannya secara percuma untuk semua orang!

SSL Certificate Digunakan Untuk:

  • Membina saluran data selamat (Encrypted Tunnel)
  • Memastikan tiada sesiapa boleh ubah isi kandung laman web
  • Menghapuskan amaran "Not Secure" di pelayar web
    • Cabaran Teknikal

    Masalah Port Python vs HTTPS

    Server Python latihan kita sedang berjalan di Port 8080 (HTTP).

    Tetapi pengguna internet mahu melawat melalui Port 443 (HTTPS) secara standard tanpa perlu menaip nombor port di belakang URL!

    Konsep #3

    Apa itu Reverse Proxy?

    Definisi "Pengantara":

    Reverse Proxy ialah sebuah server hadapan yang menerima sambungan HTTPS dari luar (Port 443), mengurus SSL Certificate, dan meneruskan (*forward*) trafik itu ke aplikasi dalaman (Python Port 8080).

    Browser (HTTPS :443)
    REVERSE PROXY
    Mengurus SSL & Certificate
    Python Server (:8080)
    Perisian Contoh

    Memperkenalkan Caddy Server

    Reverse Proxy Moden & Mudah

    Selain Nginx atau Apache, Caddy sangat popular kerana ia memohon dan memperbaharui SSL Certificate (Let's Encrypt) secara automatik 100% tanpa tetapan yang rumit!

    * Nota: Nginx dan Traefik juga popular, tetapi Caddy adalah contoh paling mesra beginner.

    Fungsi Utama Caddy:

    1. Terima HTTPS di Port 443
    2. Request SSL Certificate Automatik
    3. Pass traffic terus ke localhost:8080
    Konfigurasi Ringkas

    Contoh Fail Konfigurasi Caddyfile

    Lihat betapa mudahnya menetapkan Reverse Proxy dengan Caddy:

    Caddyfile 
    app.domainbos.com {
    reverse_proxy localhost:8080
}
    💡 Penjelasan: Halaman web app.domainbos.com di port 443 HTTPS secara automatik di-hantar ke program Python tempatan yang sedang berjalan di localhost:8080.
    Alternatif Standard Industri

    Alternatif: Reverse Proxy Menggunakan Nginx

    Nginx ialah perisian web server & reverse proxy paling popular di dunia enterprise.

    nginx.conf (Server Block) 
    server {
    listen 80;
    server_name app.domainbos.com;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
    }
}
    🔹 proxy_pass http://localhost:8080; — Menghantar trafik dari domain ke Python server tempatan.
    🔹 Nginx biasanya digabungkan dengan tool Certbot (Let's Encrypt) untuk pengurusan HTTPS / SSL.

    Caddy vs Nginx (Perbandingan Ringkas)

    Caddy: Konfigurasi mudah 2 baris, SSL automatik tersedia (Sangat Mesra Beginner).
    Nginx: Prestasi ultra-tinggi, sangat fleksibel (Standard Industri), tetapi perlukan tetapan SSL/Certbot secara berasingan.

    Pemerhatian Utama

    Tetapi... Masalah Asal Masih Ada!

    Walaupun kita sudah mempunyai Domain & HTTPS, setup ini masih bergantung kepada:

    • Public IP rumah yang masih terdedah secara terus.
    • Router rumah yang dipaksa membuka Inbound Port (80 & 443).
    • Masalah IP berubah-ubah (Dynamic IP) jika ISP restart.

    Soalan Penting:

    "Bolehkah kita *expose* website ke internet TANPA perlu dedahkan Public IP rumah & TANPA perlu Port Forwarding?"

    Jawapannya: BOLEH! 🎉

    Memperkenalkan Cloudflare

    Pintu Hadapan Rangkaian Global

    Cloudflare ialah perkhidmatan rangkaian global yang bertindak sebagai pengantara (*Reverse Proxy Giant*) di antara pelawat di internet dan server anda.

    🛡️ Perisai Serangan DDoS
    ⚡ Caching Website Laju
    🔒 Pengurusan DNS & HTTPS Percuma
    Laluan Dilindungi Cloudflare
    User Cloudflare Network Server Rumah
    Ciri DNS Cloudflare

    DNS Only vs Proxied (Awan Oren)

    DNS ONLY (Awan Kelabu)

    Cloudflare hanya memberitahu Public IP anda kepada pelawat. Pelawat terus berhubung secara terus ke router rumah anda.

    Public IP Rumah Masih Terdedah!
    PROXIED (Awan Oren)

    Pelawat hanya nampak IP milik Cloudflare! Cloudflare yang akan mengambil data dari server anda dan menyerahkannya kepada pelawat.

    Public IP Rumah Tersembunyi Dengan Selamat!
    Masalah Port Forwarding

    Masalah Port Inbound Masih Ada!

    Walaupun Cloudflare Proxied menyembunyikan IP, Cloudflare still perlu laluan masuk (*Inbound*) untuk sambung ke Router rumah anda.

    ❌ Masih perlu buat Port Forwarding di Router.
    ❌ Sesetengah ISP menghalang (*block*) Inbound Port 80 / 443.
    ❌ Masalah Carrier-Grade NAT (CGNAT) di mana pengguna tiada Public IP sebenar!
    Laluan Masuk Yang Masih Diperlukan:
    Cloudflare Inbound Port Router Server
    Solusi Muktamad

    Apa itu Cloudflare Tunnel?

    Revolusi Sambungan Outbound:

    Cloudflare Tunnel membuatkan server rumah anda membuat sambungan KELUAR (*Outbound Connection*) secara terus ke Cloudflare.

    ❌ TRADISIONAL (INBOUND):
    Internet → Public IP → Router → Server
    ✅ CLOUDFLARE TUNNEL (OUTBOUND):
    Server → Encrypted Tunnel → Cloudflare
    Analogi Mudah

    Analogi Pintu Rumah vs Tunnel

    Direct Port Forwarding

    "Membuka pintu pagar rumah luas-luas supaya orang luar dari jalan raya boleh terus ketuk pintu bilik tidur anda."

    Cloudflare Tunnel

    "Pintu pagar rumah sentiasa dikunci rapat. Komputer anda membina *terowong bawah tanah rahsia* terus ke pejabat pengawal (Cloudflare). Orang ramai hanya boleh berjumpa di pejabat pengawal sahaja!"

    Perisian Daemon

    Apa itu cloudflared?

    Agent Khas Di Server Anda

    cloudflared ialah program kecil (executable) yang dipasang di komputer server anda untuk menguruskan laluan Tunnel keluar.

    # Contoh arahan menjalankan tunnel:
    cloudflared tunnel run my-app

    Tugas Utama cloudflared:

    1. Kekalkan sambungan terowong ke Cloudflare
    2. Terima request pelawat dari Cloudflare
    3. Hantar terus ke http://localhost:8080
    Tetapan DNS Tunnel

    DNS Untuk Cloudflare Tunnel

    Berbeza dengan Direct Public IP yang menggunakan A Record (IP Address), Cloudflare Tunnel mengarahkan domain anda terus ke CNAME Hostname Tunnel!

    Type: CNAME
    Name: app
    Target / Target Host: xxxx-xxxx.cfargotunnel.com
    Proxy Status: Proxied (Awan Oren)

    🔒 Tidak ada Public IP rumah yang ditulis langsung dalam DNS!

    Panduan Keputusan

    Bila Patut Guna Yang Mana?

    Direct Public IP / Port Forwarding

    Sesuai digunakan jika:

    • Sedang belajar konsep asas networking & paket data.
    • Membuat makmal latihan tempatan (Lab Environment).
    • Perlu protokol khas selain HTTP/HTTPS yang tidak disokong tunnel biasa.

    Cloudflare Tunnel

    Sesuai digunakan jika:

    • Mahu *expose* aplikasi web rumah tanpa risiko port terdedah.
    • Menggunakan ISP berunsur CGNAT (Tiada Public IP).
    • Mahukan HTTPS percuma dan perlindungan DDoS serta-merta.
